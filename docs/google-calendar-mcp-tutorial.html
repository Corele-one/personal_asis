第一步：确认 Google OAuth 配置

1

打开 Google Auth Platform · 目标对象，确认应用仍处于 External / Testing，你的 Gmail 在测试用户名单中。测试阶段无需发布应用。

2

在 Google Cloud 的 Google Calendar API 页面确认 API 状态为“已启用”。客户端类型应为 Desktop app。

OAuth 应用名应显示为 AstrBot Calendar，客户端为 AstrBot Calendar VPS。如果页面显示其他应用或账号，先停下检查。

第二步：原只读 OAuth 流程（已完成）

这一步会由你在 Google 同意页授予日历只读权限。Python 引导脚本使用 PKCE，监听地址只绑定 VPS 的 127.0.0.1；客户端密钥和令牌留在 VPS。脚本会拒绝额外 scope、缺少 refresh token 的响应，也不会覆盖已有令牌。

1

在 Mac 的终端 A 建立临时 SSH 转发。让这个终端保持运行：

ssh -N -o ExitOnForwardFailure=yes -L 8085:127.0.0.1:8085 mac@35.209.202.207

连接首次提示 SSH 主机指纹时，只在与之前核验过的 VPS 指纹一致时继续。完成授权后按 Control-C 关闭转发。

2

在 Mac 的终端 B，把公开的引导脚本传到 VPS，再启动它：

scp scripts/google-calendar-oauth-bootstrap.py mac@35.209.202.207:/home/mac/astrbot/data/google-calendar-mcp/oauth_bootstrap.py
ssh mac@35.209.202.207 'chmod 700 /home/mac/astrbot/data/google-calendar-mcp && chmod 600 /home/mac/astrbot/data/google-calendar-mcp/gcp-oauth.keys.json && chmod 700 /home/mac/astrbot/data/google-calendar-mcp/oauth_bootstrap.py && python3 /home/mac/astrbot/data/google-calendar-mcp/oauth_bootstrap.py'

脚本会在终端显示一条临时 Google OAuth URL。不要把 URL、回调地址或授权过程截图发到聊天里。

3

在 Mac 浏览器打开终端 B 打印的 URL，选中已加入测试用户的 Gmail。Google 同意页出现后，仔细核对：

  • 应用是 AstrBot Calendar；
  • 请求的唯一数据权限是 calendar.readonly，含义为查看日历和活动；
  • 没有写入、修改、删除日历事件的权限。

只有以上信息都匹配且你同意时，才在 Google 页面点击继续/允许。如果显示更广权限、另一个应用或另一个账号，请取消并停止。若页面空白，刷新或换浏览器后重跑脚本；不要盲目继续。

4

Google 回调成功后，VPS 终端应显示“Read-only OAuth token saved privately”及“calendar.readonly”。随后终端 A 按 Control-C 关闭 SSH 转发。如果 Google 页面空白或范围不符，先在终端 B 按 Control-C 取消流程，再关闭转发；排除原因后再重新运行。

不要使用上游 MCP 的 auth / manage-accounts add 来获取这次令牌：它们默认申请完整 calendar scope。也不要用 gcloud ADC 流程；它会额外要求 cloud-platform。

第三步：检查私密保存结果

在 Mac 另开终端执行以下只检查权限和授权范围的命令。输出不包含令牌内容：

ssh mac@35.209.202.207 "stat -c '%a %n' /home/mac/astrbot/data/google-calendar-mcp/tokens.json && python3 -c 'import json; p=\"/home/mac/astrbot/data/google-calendar-mcp/tokens.json\"; t=json.load(open(p))[\"normal\"]; assert t.get(\"scope\")==\"https://www.googleapis.com/auth/calendar.readonly\" and t.get(\"refresh_token\") and t.get(\"access_token\"); print(\"scope and token fields OK\")'"

期望权限是 600，末行显示 scope and token fields OK。若失败，不要贴出文件内容；把不含令牌的报错文字发给我。

成功后，脚本只在 VPS 写入 tokens.json。客户端 JSON、访问令牌和刷新令牌都不要复制到 Mac、聊天、工单、Git 或命令参数。

不要手工改 data/mcp_server.json 或切换 AstrBot MCP 的全局访问白名单。仅把工具设为 admin 仍不能证明群聊隔离，可能影响其他插件。

写入授权与激活状态

写入代码已通过 VPS 实际 AstrBot SDK 合成预检并部署；Google 授权和 VPS 激活已完成。Google 官方的写入 scope calendar.events.owned 允许查看、创建、修改和删除你拥有的日历中的事件；同时保留 calendar.readonly 以继续读取你可访问的日历。授权范围详情见 Google 官方文档。

已核验：Google 只授予 calendar.readonly 和 calendar.events.owned；AstrBot 配置已启用，服务启动日志确认写入提案工具已上线。
1

下列步骤仅供以后令牌到期时重新授权参考。Mac 终端 A 建立临时回环转发并保持运行：

ssh -N -o ExitOnForwardFailure=yes -L 8085:127.0.0.1:8085 mac@35.209.202.207
2

在终端 B 启动已放在 VPS 私密目录的扩权脚本：

ssh mac@35.209.202.207 'python3 /home/mac/astrbot/data/google-calendar-mcp/upgrade_calendar_write.py'

在浏览器打开脚本打印的临时 URL。核对应用为 AstrBot Calendar、账号正确，且仅请求上面列出的两个scope。脚本用 PKCE，收到的scope不完全相符或缺少刷新令牌时，会保留现有只读令牌；成功升级时也会先把原令牌保留为VPS私密的 0600 备份。

3

看到“Calendar scopes verified”后，在终端 A 按 Control-C 关闭转发，再执行一次性激活脚本：

ssh mac@35.209.202.207 'python3 /home/mac/astrbot/data/google-calendar-mcp/activate_calendar_write.py'

该脚本会再次校验scope、备份配置、打开写入开关并重启AstrBot。随后你可在本人私聊提出新增、修改或删除事件；机器人先给完整预览与确认码，你发送 /life calendar confirm <确认码> 才会执行。五分钟有效、一次使用。取消用 /life calendar cancel <确认码>。

写入目前仅支持单个、非重复事件；创建时不能邀请参会者，修改／删除含参会者的事件会被拒绝，也不发送通知。暂不支持批量写入、重复事件和日历共享管理。每次操作的Google结果未知时不会自动重试；先到日历核实状态。
