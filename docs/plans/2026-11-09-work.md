## 1. 独立的 Work

入口是用户已安装 Alma 的 iPhone，执行端是 VPS 上的官方 Alma Server。用户主动在 Alma 开始工作；飞书 Chat 只提出建议，不派单、不建立 Work、不传当前聊天上下文。

有 Mac 时由用户直接使用 Mac／本地 Pi；不建立 Alma→Mac 连接、不唤醒 Mac、不新增远程本机工作队列。既有 pi_sync 和获准资料副本独立保留，VPS 只使用已有或经授权取得的副本。

Work 具有自己的进程、数据目录、工作区、配置、凭据范围、升级、回退和停用流程，不导入 AstrBot Agent／会话／生活插件运行进程。它可在不接入共用服务的条件下先独立运行，后续选择性接入工具与记忆。模型由 Alma 原生配置管理，不引入共用网关。

关联文档：[Chat 计划](2026-11-09-chat.md)、[共用能力与选型](2026-11-09-shared.md)。

## 2. 已核实与未核实

- 官方 v0.4.139 明确 Alma Server 支持无桌面的 Linux x64／arm64，以及 iOS 经 relay 访问；后续 v0.4.530 仍发布 Server。[官方介绍](https://github.com/yetone/alma-releases/releases/tag/v0.4.139)
- 已下载并校验 v0.4.530 x64 官方包，静态读取根 README 与 `lib/server.mjs`；包含 Node 运行时、MCP、Skills、工具、配对和插件事件实现。包不是应用完整开源许可的证据。
- Server仅回环监听，使用独立身份／目录与官方加密relay。最初ask策略的API合成允许／拒绝／离线拒绝通过，但本人iPhone实际遇到no-window拒绝；后续本人选择常规工具auto执行，手机文件任务通过。该选择没有修复原生手机审批，历史结果分开保留。
- 桌面 Computer Use、屏幕／窗口采集、活动记录、可见浏览器面板及本地 embedding 等不能直接用于 Server。内置浏览器在 headless 路径有明确拒绝分支；网页获取应另验 API／MCP 路线。
- 现有 VPS 约 0.94 GiB RAM，已有 AstrBot、Dashboard、Calendar MCP 等进程。可用内存是瞬时快照，不能由约 203 MiB 压缩包推断运行占用。`/tmp` 仅约 482 MiB，安装与数据应使用已检查有容量的持久盘。
- 初始128MiB堆限制下出现过SIGABRT，根因未留足诊断；已调整为256MiB堆／384MiB内存硬上限／128MiB swap并加入固定分类诊断。短窗口健康不证明长期承载；不能依赖未固定latest或声称并发验收已完成。
- MiMo 2.6 Flash与DeepSeek V4 Flash均已原生配置，默认MiMo；工具选择模型复用MiMo。初始化器错误的32K模型窗口已改为1,000,000 token，保留输出4096／自动压缩80%。Alma模型容量与Chat Router出站32K／64K预算分属不同运行时。

日常使用不要求说“在VPS Work中”、指定Bash或手工新建Project。默认工作区自动接收任务；Alma图标入口绑定“个人助手 · 主对话”，普通Chat各自保存消息历史，Project组织相关文件／目录与配置。本人要求减少人为限制后，已开放原生技能、Agents和按需子任务，取消只用单任务／前台的工作说明；资源隔离和其他业务写入确认继续保留。

来源：[Server 发行页与包](https://github.com/yetone/alma-releases/releases/tag/v0.4.530)、[Alma MCP](https://alma.now/docs/features/mcp)、[插件事件](https://alma.now/docs/plugins/hooks-events)。

## 3. 阶段与目标

### W0：容量、版本与隔离设计

不依赖 Chat 更新即可开展。

- 重新测服务与磁盘基线，选择固定版本、安装目录、数据目录、工作区、服务身份、监听和资源限制；先准备独立停用与回退路径。
- Work 运行权限与 AstrBot 私密配置分开，不能因为使用同一节点就获得生活库、Calendar Token、插件配置和其他项目的任意读写。普通目录限制不冒称 OS 沙箱。
- 仅复用明确批准的模型账号；不自动导入 Mac Keychain 或订阅，不把记忆提供商默认值当成授权。
- 列出允许的首批能力：Work 自己的文件与终端、指定资料只读工具。Journal／日历／平台写入暂不直接暴露。

阶段目标：有可复核的资源、权限、版本和停用方案。若容量不足，先调整部署形态或资源，不通过移除 Chat 必要能力来勉强共存，也不同时增加 Pi／herdr／本地向量模型。

### W1：独立 Alma Server 与 iPhone 配对

- 在独立目录／服务中启动，仅回环监听，保留独立数据；不公开代理高权限本地 API。
- 通过官方 iOS relay 流程配对。令牌通过用户安全输入与受控配置处理，不贴进聊天、参数日志或 Git。配对属于账号接入，不代表授权任意资料写入。
- 原计划设置询问并验收手机允许／拒绝／取消；实测iOS原生审批未接通，不能声称已修好。本人随后明确要求常规Bash不逐条批准，本阶段改为Work自有文件／终端原生auto，保留系统隔离、资源限制及独立停机／重启验收，真实日记／日历／平台写工具继续不接入。
- 配置少量现有模型，测试普通问答及有界合成文件任务、流式返回、取消、重连与持久化。真实模型调用、手机真人验收与合成检查分别记录。
- 观察已测空闲／任务资源及对Chat的影响；原生子任务与后台执行可按需使用，但不把开放开关写成并发容量已通过。

阶段目标：Mac关机时iPhone仍能按本人选定的执行策略独立完成一项有结果的VPS Work；停Work后Chat和PWA继续正常。原生手机逐次审批缺口单列，不以auto执行冒称该交互已通过。

### W2：接入共用资料工具

- 复用现有共享资料库、五彩完整读取等业务，采用 MCP 或已验证的官方扩展。维护独立客户端，不从 Work 直接导入 AstrBot Event 对象或挂载它的活动数据库。
- 首期只读；返回来源、版本、取得时间、覆盖和继续游标。全文需读完整保存版本，不能把快照、划线或搜索摘要冒充全文。

- 合成工具与实际来源读取分开验收；单个工具失败不破坏 Work 自身会话。

阶段目标：同一获准来源能与 Chat 核对版本；不需要 Chat 在线即可读取共用资料服务；撤回来源后 Work 停止使用。

### W4：原生模型配置与执行稳定性

用户已取消 Magpie 评估。Work 使用 Alma 原生提供商配置，与 Chat Router 独立维护。

- 明确 Work 的默认与手动模型，不改 Chat 默认模型。首批仅批准的 API 来源，不自动扫描账号或新增订阅。
- 验证工具能力声明、思考档、流式／多模态、上下文容量与真实模型回执，避免工具退化成纯文本或错误识别模型能力。
- 核对 Alma 自身的重试、取消和工具防重路径；未知结果不能自动重发，也不能重跑已经完成的工具。
- 单个提供商不可用时明确报告，不假称已更换模型；当前结果未知时不能以手动选型为由自动重放。

阶段目标：固定测试任务的实际模型与执行结果可核对，工具只执行一次；取消和不可用状态清楚，资源与延迟有实际记录。不新增共用网关或新的模型账号；Alma原生工具／技能选择所需的辅助模型复用已有MiMo，不引入另一套外部分类服务。

### W5：只读接入 PWA Overview

- 提供有界只读状态快照：已部署／未部署／运行／未知、版本、观测时间、能力就绪与有限任务统计。只有接口实际返回的字段才展示。
- PWA 通过适配器或独立快照取得状态，不读取 Alma 内部数据库，不导入 Server 模块，不持有可执行终端的配对权限。
- Work 停用、升级或接口变化时，Overview 显示未接入／过期／未知；Chat 生活看板继续可用。
- 如有受支持的 Alma 打开方式，只提供导航；不编造深链，不在 PWA 建立工作派发、shell 或会话控制台。

阶段目标：用户能在 Overview 分辨“没接入”“上次正常”“当前已观测正常”；停 Work 不导致 PWA 页面失败。

### W6：Work 轨迹与可选能力扩展

- 从官方可用的 transcript／工具事件／插件 hook 取得轨迹：目标、输入、工具、材料、成果、失败与本人修订；与 Chat 使用相同事件含义，但会话、存储归属与发布独立。
- 不采集隐藏推理、不从没有反馈推断采纳；AI 生成的报告不自动成为本人经历或学习完成证据。
- 可选 Pi／herdr 只在有具体能力缺口时另立小范围验证；不因 Mac 已用 Pi 就把 VPS 也强制换 Pi，不把多个官方组件的文档拼接成已支持的全链路。
- 扩展网页／附件等能力时先复用已获准 API／工具；新增来源账号、云端处理和平台写入分别处理，不从配对授权推导。

阶段目标：至少一项完整 Work 能回看材料、工具与最终成果，并记录一次用户纠正；删除或撤回相应资料时，派生轨迹的可见范围有明确处理。

## 4. 独立维护与失败处理

| 变化／故障 | 必须保持的行为 |
|---|---|
| Work 未部署／停用 | Chat 正常；PWA 显示未接入，不连接 Mac 接替 |
| Work 升级 | 固定版本、独立停机；Chat 无须重启；数据兼容性先核对 |
| Mem0 离线 | Work 保留自身会话；不伪称读取长期记忆；Chat 不因 Work 停用而失去权威记忆 |
| 模型提供商不可用 | 明确失败；未知的当前请求不自动重放，后续新请求按原生配置处理 |
| 用户取消／手机断连 | 保留实际状态与结果；未知不自动重放。Work自有终端按本人最新auto策略执行，未接入的外部业务写入仍须具体确认 |
| 代码回退 | 不用旧 Alma 数据覆盖新对话或新成果；涉及 schema 迁移先核对兼容性 |

Alma 自身有升级与依赖变化，维护计划需要定期核对 release、固定版本及最小回归。完整应用源码未核实公开，这一可控性限制须保留在决策中。
