# Mem0 初始化与首次可用验收

更新：2026-11-10（Asia/Shanghai）。状态：**M1功能／鉴权／恢复通过，资源门槛未签收；个人初始化待实施**。独立合成服务已部署验收后停止并禁用开机启动，代码／私密数据保留；未导入个人记忆或开启自动保存。本文细化[共用记忆计划](2026-11-09-shared.md)的 M1–M3，不另建第二套记忆系统。现状见[说明](../shared-memory.md)及[验收](../validation/mem0-m1-20261110.json)。

## 1. 是否需要初始化

2026-11-10后续安排：本清单暂缓执行，当前优先共用资料及两端使用质量；不因保留此清单就默认下一步继续M2／W3或扩容。未来恢复共享个人记忆时，以下初始化与验收要求仍适用，见[阶段取舍](../shared-memory.md#当前取舍2026-11-10)。

**需要，而且安装 SDK 不等于初始化完成。** 要分别完成服务／存储初始化、个人内容初始化和客户端接入验收。个人内容可以从空库开始逐渐积累；但本项目已有获准背景，首次上线应核对并迁入其中仍有效的稳定偏好和明确决定，不能让用户重新讲述所有背景，也不能把历史摘要整体认作当前事实。

记忆属于核心使用能力。将本清单列为近期优先实施项；Chat C2 记忆部分、Work W3 分别通过自己的首次可用验收后，才可称该入口“共享记忆可用”。基础 Chat／Work 仍可独立运行，不能因记忆未就绪而阻塞普通对话或文件工作。

由一个实施方负责权威服务和首次导入，建议继续由 Chat 侧承接。Work 只消费发布后的接口，不重复建库。以下 I0–I7 是执行步骤，不替换既有 M 阶段：

## 3. I0：执行前核对

1. 读取 AGENT.md、本清单及 Chat／Work 当前计划；只读核对线上实际状态，不用旧回执代替当前观测。
2. 核对试点虚拟环境与依赖锁、合成数据目录、已安装服务和监听；检查是否已有后续实施，避免覆盖已有真记忆或重复启动 SDK。
3. 记录当前内存、swap、磁盘及 Chat／Work 负载；准备独立代码／配置回退。真实库、原会话、凭据和调用账本不进入 Git。
4. 核对 VPS 当前仍存在且获准使用的 `life_context` 初始化背景和 `personal_profile`。历史曾发布的条数不是当前清单；已删除／撤回的背景不从 Mac 旧快照或备份补回。

## 4. I1：服务与存储初始化

1. 沿用独立虚拟环境与 `mem0ai==2.2.1` 基线，复核[依赖锁](../validation/mem0-pilot-20261109.requirements.txt)。如需换版本，先在合成环境重新验收，不直接升级现有生产依赖。
2. 建立专用服务身份和持久私密目录。建议布局为 `/var/lib/personal-asis-memory/` 下的 `qdrant/`、`history.sqlite3`、来源／版本／撤回收据；实际采用的目录写入运维文档。目录 0700、私密文件 0600。与试点 `synthetic_personal` collection 分离，正式 collection 不带入合成事实。
3. 显式固定 Qdrant local 路径、collection、`history_db_path`、embedding 模型和 768 维配置。由同一个进程持有 local 存储；客户端不能自行打开目录。服务每次启动加载已有库，不清库、不重复执行首批导入。embedding 模型／维度变化另做迁移，不能混写旧 collection。
4. embedding 复用已获准的 VPS Google 账号。候选抽取优先验证既有 VPS MiMo；固定实际模型、端点、超时及结构化输出契约，若改用既有其他模型，单独记录通过结果。只发送必要本人原话及有界消歧材料；不启用默认新账号或新增提供商。
5. 通过受限私密配置提供必要凭据，不给 Work 读取 AstrBot 配置的权限，也不整份复制其配置。`MEM0_TELEMETRY=false`；关闭正文、密钥和上游错误正文日志。Graph、本地模型和 reranker 保持关闭。
6. 只开放经过鉴权的本机接口，客户端凭据分别管理；服务端绑定固定本人身份。查询强制 user scope，按 ID 读取／修改／删除／history 也须核对归属，不能相信模型传入的 user_id 或 memory_id。agent／session 仅作来源，不能意外切成多套个人记忆。
7. 提供最小的查询、保存、更新、查看、撤回和状态接口。状态区分“服务可达／存储就绪／内容初始化完成／自动保存启用／客户端接入”，不只报告进程 active。接口名称及请求结构在实施时固定并同步客户端；本文不冒称这些接口已存在。

## 5. I2：先完成 M1 合成验收

1. 将 14 项语义契约变成可运行验收，覆盖真实候选抽取。`infer=False` 仅跳过 Mem0 再抽取，仍有 embedding 调用；试点禁止 LLM 生成的设置不能证明自动抽取正确。
2. 经校验的候选用 `add(..., user_id=..., metadata=..., infer=False)` 入库；复用 Mem0 search／update／delete／history，不自研替代引擎。search／get_all 参数按固定版本核对。
3. 验证一次性要求、引用、AI 建议、生活事件不被全局化；同范围明确纠正替代旧版本，同名不同项目分别保留，取消计划不变成已完成。
4. 两客户端基于同一预期版本并发纠正，只允许一个成功，另一个返回冲突。重复来源只能有一份有效结果；写库和来源收据中断后可核对恢复，不依赖 SDK 存储与适配收据天然跨库原子提交。
5. 撤回后搜索不命中、客户端缓存失效、旧聊天重读不复活；检查 Mem0 history 是否仍保留旧正文，明确区分“停止参与回答”和“清除派生正文”。若不能实现约定的删除范围，先解决，不宣称彻底遗忘。
6. 验证未认证、错误客户端和越权 ID 均被拒绝；服务失联时 Chat／Work 基本功能继续，相关问题说明记忆不可用。超时或未知结果不自动重发。
7. 记录真实模型／向量调用次数、耗时和费用可见范围。与正常 Chat、Work 串行轻任务共存，至少测空闲、保存／检索、重启及持续观察；建议跨一个正常使用日，记录内存／swap／OOM 与两端延迟。发现挤压或重启循环先停止推广，不擅自提高预算或资源上限。

以上结果齐全才通过 M1；短时 CRUD 成功不能跳过此步。

## 6. I3：准备个人起始内容

### 首批取什么

| 来源 | 初始化处理 |
|---|---|
| VPS 当前已批准的背景／profile | 逐条核对原始出处、原有授权和后续修订；仅迁入仍有效的稳定偏好／明确决定 |
| 本人明确选中的历史表达 | 按选定消息／范围读取，保留原话与日期；没有选择不后台全量回扫 |
| 新表达 | I5／I6 启用后按相同语义契约自动保存，不要求每条重复确认 |
| 历史生活／学习／健康事实、任务进度 | 留在原证据系统按需查询；首批不扩展为个人画像，不因资料存在推断完成或掌握 |
| AI 回答、引用、收藏文章、项目资料与计划草案 | 不直接认作本人偏好或决定；仅明确本人采纳且有原话依据的部分可成为候选 |

具体操作：

1. 建立有界的私密候选清单，一条表达拆分为必要的独立记忆，不把整个 profile 文档作为一条事实。每条记录至少有：候选 ID、拟保存文本、本人原话／可定位出处、来源版本或哈希、表达时间、内容类型、适用项目／范围、当前有效性及替代关系。
2. 从旧背景回查后续明确修订、取消和撤回。不得只凭“日期较新”或向量相似就认定覆盖；无法消歧的冲突标待核对，暂不进入有效记忆。计划保持计划身份，历史状态不自动升级成当前事实。
3. 展示首批拟导入内容及来源，列清保留、合并、过期、冲突与排除项。已有具体批准在原范围内可复用；若新生成／修改背景或扩大历史范围，先准备完整候选，再按既有背景确认规则取得对应授权。不把本次“写计划”当作已经批准了尚未展示的个人内容。
4. 首批条数由可核对内容决定，不设凑数目标。没有可用候选可明确以空库启用增量保存，但必须说明“历史背景未迁入”及原因，不能写成已有完整个人记忆。

## 7. I4：首次导入、去重与读回

1. 建立私密导入批次：固定来源清单版本／哈希、对应授权依据、候选内容、抽取版本及来源去重键。来源在预览后改变则该候选失效，重新核对。
2. 通过唯一权威服务导入，来源去重键与导入批次绑定。新增前核对已有来源和同范围有效记忆；明确替代采用受版本约束的更新，不机械追加互相矛盾的记录。来源／撤回收据只承担核对，不另存一套权威画像。
3. 每条持久记录来源→memory_id→有效版本及结果；中断区分成功、明确失败、未知。未知先读回核对，不自动再次调用抽取或重复写入；只有核实缺失后才显式恢复未完成项。
4. 用相同本人身份逐条读回原文／metadata，再以不同措辞搜索，核对每条实际可召回、来源可定位、适用范围正确。重复执行同批次应新增 0 条。
5. 冷启动服务后再读回，确认正式目录持久化。候选数、成功数、排除／冲突／未知数及版本均在私密回执可核对；Git 仅保存合成样例和脱敏计数。
6. 处理旧背景注入：已迁移的偏好／决定只使用 Mem0 当前版本，旧 profile 同项不再重复注入或覆盖纠正。未迁入的历史背景仍保留日期和身份，按原许可按需读取；不重写／删除原背景私密文件，不扩展 Work 对历史生活资料的访问。

## 8. I5：Chat 首次可用与管理入口

1. 独立启用检索及新表达自动保存开关，明确启用时间和来源游标；不把积压旧聊天当成启用后的新表达。已完成回答和工具链不因记忆失败重跑，不声称失败／未知的记忆“已保存”。
2. 先按当前问题相关范围读取有效记忆，再准备回答；记录实际参与的 memory_id／版本及来源，不能只让模型自己声称“我记得”。保存失败与查询无命中分别处理。
3. PWA 提供当前记忆、来源、范围／时间、修订历史及纠正／撤回入口；沿用认证、Origin／CSRF 和文本渲染规则。修改绑定明确目标与预期版本并显示回执，不暴露原始服务管理接口。
4. 用合成客户端验证后，由本人自然私聊确认：明确表达一个稳定偏好→另开新会话正确使用→纠正后新会话只使用当前版本→撤回后不再使用。另测一次性要求和服务离线。不发送飞书测试消息，真人验收缺失单独记录。
5. 重启 Chat 与记忆服务后复测；Overview 分别显示初始化、最近成功读写、自动保存开关及错误／过期状态。仅服务在线、空库或只完成试点时不能显示“记忆已初始化并可用”。

## 9. I6：Work 消费同一实例

1. 通过 Alma 支持的 MCP／扩展访问同一权威服务，使用独立客户端凭据和相同本人 user scope；不导入 AstrBot 运行模块，不复制 Qdrant／history。
2. Alma 原生重叠的个人自动记忆保持关闭；任务文件和工作进度仍由 Alma 保存。检索与写入只处理获准的偏好／决定，不以共享记忆名义开放原生活库。
3. 验证 Chat 保存→Work 新会话召回，Work 同范围纠正→Chat 使用新版本，任一端撤回→另一端停止使用；缓存命中前校验有效版本，不能仅等待长 TTL 到期。
4. Work 停用时 Chat 仍可读写记忆；Chat 停用时 Work 仍可访问独立记忆服务；记忆服务停用时两端保留自身基本能力。分别记录实际 MCP 注册、模型调用、手机 UI 结果。

## 10. I7：备份、恢复及日常维护

首次上线前即完成备份／恢复演练，不推迟到可选 Mac M4：

1. 停止记忆写入并关闭 local 存储持有进程，制作同一检查点的 Qdrant、history、来源去重／版本／撤回收据和非密钥配置备份；不直接复制仍在写入的文件冒充一致备份。
2. 在隔离位置恢复合成备份，核对数量、来源、当前版本、查询及撤回；正式恢复前先保留当前库。老备份必须先应用更新的撤回／修订记录再开放读取；无法核对缺失范围就保持离线，不能复活旧偏好。
3. 记录备份保留期、位置、访问权限和清除办法；忘记操作明确说明当前索引、history、客户端缓存、原聊天与备份分别处理到哪里，不承诺未执行的全副本删除。
4. 日常增量保存不反复跑初始化，也不定时重扫所有历史。模型、维度、schema 或来源范围变化另起迁移批次；导入／升级回退不覆盖新记忆、撤回或原聊天。
