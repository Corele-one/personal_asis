# Chat 后续更新计划

日期：2026-11-09。状态：供后续新对话 coding & build。本文只定义计划，没有修改线上服务或真实资料。

## 1. 目标与维护边界

Chat 继续使用 VPS AstrBot 和本人飞书私聊，负责自然交流、足够深入的讨论、日常资料查询、主动记录及日常事务。Chat 可以建议本人到 Work 执行合适的任务，但不创建、派发或接续 Work，不自动交接当前上下文。

Chat 的代码、profile、会话、生活数据、发布与回退独立于 Alma。Work 未安装、离线或升级时，Chat 仍可工作。新记忆采用独立开关，不能将其一次故障变成整段日常对话不可用；需要它才能回答的问题明确说明缺口。用户已取消 Magpie 评估，继续使用现有 Router。

PWA Dashboard／Overview 是 Chat 计划的核心交付，不是可省略的尾项。共用能力与候选选择另见 [共用计划](2026-11-09-shared.md)；Work 的实现另见 [Work 计划](2026-11-09-work.md)。

## 2. 当前基线：承接今早修复

2026-11-09 只读核对：本地 `ecf6a39`，VPS Router 1.1.0 发布 `20261109_110914_148969`，在线四份核心模块与发布清单一致。本人配置原生摘要 Provider 为空、`max_context_length=-1`，原生外层 fallback 为空；虚拟 Provider 历史缓冲与真实出站预算分别管理。

已经做过的修复包括：时间块不再重复成为用户消息；明确单轮指定模型；当前用户轮和工具链绑定；工作摘要预算与覆盖；旧会话只读回查；保留原始历史缓冲。后续以它们为回归基线，不能删除旧插件后把同样的能力丢掉。

这些检查不等于日常质量已经验收。近期对话中的 PWA／Magpie 讨论仍误调 `life_organize`，但被工具拒绝；最近会话仍包含 Scheduler 合成 user 和任务报告。催睡规则目前仍开启。以上是新计划需处理的范围。

## 3. 阶段和交付

### C0：形成可回退基线

实施前重新核对绑定本人、当前 profile／模型／插件、服务、提醒策略、摘要及回查配置，留私密回退。原话、调用账本和生活数据不随代码回退覆盖。

建立合成质量用例，取材于已确认故障类型，不提交私人聊天原文：明确换模型、带引用／时间块的任务、多步骤资料读取后总结、普通架构讨论、周回顾、后台任务结束、跨会话回查和长对话。

验收：能够区分原始材料、工作摘要、长期记忆和后台通知；已有 SDK 与工具只执行一次的关键回归继续通过。此阶段不等待 Alma 或 Mem0 上线。

### C1：删除催睡，隔离后台任务，纠正工具选择

优先级：P0。

- 停止催睡专用 worker／排期与自动恢复路径，清理启用入口、管理命令、系统提示及每轮说明。部署迁移不得因重启重新打开。
- 移除催睡对普通回答和晚安回执的干扰；引用中的“晚安”或历史任务不能改变当前请求。保留既有自报作息原话、已确认记录与真实投递回执。
- 不删除其他明确事项提醒、每三日简报、周报或无关原生 cron。已发送平台消息及原始聊天不是可假称已清除的上下文。
- Chat 的工作副本与摘要停止使用已失效的催睡规则；必要时作有范围的摘要重建。原始聊天不批量改写，不用旧备份覆盖新消息。
- Scheduler／简报／提醒在独立执行会话中运行，结果作为有来源通知交付，停止往普通 Chat 历史写入伪 user 提示和任务完成报告。保留既有持久防重及未知结果规则。
- 普通系统讨论不调用生活整理；保留 `explicit_life_entry_required`，不能通过放开 gate 来让错误调用“成功”。提高工具描述、按入口供应工具和当前请求意图识别。

验收：催睡 policy／worker／提示均退出有效路径；重启与跨日不恢复；普通 Chat 不再被催睡打断；日常提醒和简报保持独立；架构讨论不再误调用生活写工具。拒绝回执和真实成功状态分别呈现。

### C2：补齐资料访问与跨会话记忆

优先级：P1。资料查询先行，Mem0 适配依赖 M1 通过。

- 复用 `shared_store`／`shared_knowledge`，补日期范围枚举、来源过滤、相关排序、分页原文与覆盖统计。“上周复盘”要能读取完整目标日期窗口，而非只取最近聊天或用空搜索判断无记录。
- Life、Study、五彩、普通聊天和主动随记分开理解；返回最新同步时间、来源版本、已读范围和未覆盖部分。没有记录不等于没做，没有检索命中不等于没有该资料。
- 旧会话继续按需回查；新话题可由用户菜单／卡片选择新建或切换，界面标明当前会话。用户没有 `/new` 习惯不应成为长期串线的前提。
- 接入独立 Mem0 服务的同一本人 user scope；自动保存稳定偏好和明确决定，按来源及范围检索。Chat 不等待 Work 可用。
- 历史全量提取默认关闭。首期从启用后的新表达及用户明确选中的历史候选开始，不把已被旧摘要改写的历史包装成完整原文。

验收：新会话可检索同一条有效偏好；临时要求不全局化；AI 建议不成为本人决定；纠正／撤回后旧版本不再影响回答；断开记忆服务时显示范围限制。周回顾能列清实际材料范围。

### C3：改进现有 Router 与模型可见性

优先级：P1；不是 C1 的前置条件。

模型数量有限，保留今早已修复的 Router，不引入 Magpie 或其他新网关。围绕现有模型改善选型规则、上下文完整性和真实状态展示，保留 AstrBot 的 Agent 工具循环、跨会话回查和既有额度记录。职责边界见 [共用计划第 3 节](2026-11-09-shared.md)。

必须交付：

1. 日常／深入／指定模型的明确语义，分类只看当前真实意图；用户显式选择优先，不用模仿文风冒充切换。
2. 一轮工具链的模型与状态稳定；实际最终模型可核对，规则命中、降级原因和主生成分别记录，不默认增加额外分类模型调用。
3. 限流、额度、明确拒绝与未知结果分别处理；证明超时／断线／取消不重发，工具不重跑。
4. 原生摘要／token 缓冲的今早修复保留；同一会话仅一条工作压缩路径，不能重新启用原生持久化压缩来覆盖历史。
5. 保留当前 Router 版本回退；仅修改本人目标 profile 和适用入口，不自动更改其他会话、提供商或 Mac 配置。

验收：相同合成任务比较改动前后的选型正确性、真实模型、工具成功率和延迟；再做必要且有界的真实模型验收，平台由本人自然使用。保持未知结果不重发、已完成工具不重跑。未达到目标时回退本次改动，不阻塞其他 Chat 阶段。

### C4：Critic 与语义 Journal 整理

优先级：P1–P2。

Critic 是 Chat 的判断质量要求和按需工作方式：默认不讨好、不无证据归因；讨论决定时指出目标、关键假设、反对证据与一个可验证行动。对准推理和选择，不对本人下人格／心理诊断。先用现有引擎完成，默认不常驻第二个 Agent，也不让每次交流都增加审阅模型调用。

Journal 新增与原话并行的语义草稿：去噪、主题归并、重要推敲、已采纳结论与后续线索。保留本人原话和手写权威；用户表达、AI 提议及明确采纳分别标识，不让 AI 的赞美自行成为用户感悟。

普通聊天可生成“精华候选”，不自动成为 `/life` 或正式日记。用户选中候选或明确要求整理后进入待确认草稿；Mac `pi_sync` 保持完整预览和精确“确认写入”。设计新的来源收据，使修订／删除／重复同步不会产生第二份摘要或覆盖手记。

验收：用观点尚未决定、AI 建议未采纳、混合学习／生活、多日和图片案例核对归属；模型整理失败保留草稿，不静默机械追加。PWA 能显示草稿及其来源／确认状态，但不能在 VPS 上声称已写入 Mac。

### C5：日历批次与链接获取／剪藏

优先级：P2。

日历：将单个内存 `calendar_pending` 改为持久批次，完整预览后选择全部或部分提交；等待确认不阻塞 Chat。支持唯一绑定预览版本的按钮或自然语言确认，多个批次时先选目标。逐项保存未执行／成功／拒绝／未知，不把 Google 批量操作当成原子事务；未知项只读核对后再决定续办，不能整批重放。范围继续以已授权 owned 日历、非重复事件、无参会者及不通知为基线，不因批量顺带扩权。

链接：区分“读这个”“保存这个”和“扩展相关信息”。先按确切 URL 查五彩保存版本；全文按游标读完，未完成不做完整文章解读。Agent Reach 或经验证的搜索／抓取能力负责获取，五彩负责归档。当前 VPS 五彩工具只有读取，新增剪藏须先核对官方写接口及确认路径，不能假称任意 URL 都能取得或保存全文。

验收：多个日历提案不互相阻塞；重复确认只执行一次；事件改动使旧预览失效；取消不影响其他批次。链接区分原站现版、五彩保存正文、划线／批注、失败及覆盖不足；保存成功必须能回查。

### C6：飞书交互与会话可见性

优先级：P2，Emoji 等独立小改动可提前。

- 卡片显示当前会话名称、实际模型、是否有跨会话记忆参与、处理或待确认状态；支持新建／切换／归档本人的 Chat 会话。卡片只管理 Chat，不派发 Work。
- 使用官方机器人固定菜单；发送 `/` 或帮助后返回命令卡。输入框尚未发送时的实时斜杠补全，必须核对客户端与开放能力，不照搬飞书文档编辑器的菜单承诺。
- 正文展示层把已知表情占位映射为 Unicode Emoji；不修改来源原话、代码和引用。
- 飞书 reaction 用平台支持的表情类型，在接收／处理中／待确认／失败时更新；不等同正文 Unicode。绑定消息 ID 去重，失败不影响主回答，也不制造多次回复。

验收：切换后下一条进入目标会话；重复／过期卡片回调不改错会话；收消息有轻量状态反馈；引用与代码里的 `[捂脸]` 不被无差别替换。

### C7：PWA Overview／Dashboard 与 AI Trajectory

优先级：Overview 基础在 C1 后即可交付，不等所有后续功能完成。

**Overview** 是快速总览：近期生活／学习线索、待确认项、最近同步时间、Chat／记忆／现有 Router 状态，以及可选的 Work 观测状态。每项标明真实状态、来源和更新时间；没有 Work 状态适配器显示“未接入”，超时显示“未知／上次观测”，不把 Mac 最近同步显示成实时在线。

**Dashboard** 是深入查看：保留当前生活记录、Habits、学习日历、持续目标、回顾、Mac 选定摘要及纠正入口；增加 Journal 草稿、日历批次、记忆当前版本／来源／历史／纠正／撤回，以及路由摘要和可见交互轨迹。现有自报作息记录保留，删除的是催睡规则。

PWA 不复制第二套权威数据。每个区块从对应业务接口读取；Work 仅提供可选只读快照，Work 离线不阻塞 Chat 看板。认证、Origin／CSRF、目标版本、原话保留及敏感 API 不缓存规则继续有效；不公开代理 Alma 管理端口，不新增通用 shell 或工作派发面板。

AI Trajectory 记录可取得的用户输入、模型和工具、来源、失败／纠正、成果版本及本人明确采纳／否定；不采集隐藏思维链，不根据无反馈推断采纳、掌握或实际投入时长。与 Work 可使用相同事件格式，但分开归属；不把轨迹事件自动灌成个人事实。

验收：桌面与手机可读；Work 停用／状态过期／记忆服务不可用时总览仍能打开；未认证不能读取私人内容；纠正回执与 Journal 写入状态不混；新增来源能回到真实证据。
