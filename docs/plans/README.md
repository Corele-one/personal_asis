## 已确定的边界

1. Chat 与 Work 分别拥有运行进程、会话、配置、发布、回退及验收，任何一方停用不应导致另一方不能基本使用。
2. AstrBot 保留足够的日常推理与工具能力。飞书只建议用户切到 Work，不派发工作，不自动复制当前聊天上下文。
3. 用户已在 iPhone 安装 Alma。远端 Work 面向 VPS，不建立 Alma→Mac 控制连接；有 Mac 时由用户直接本地执行。已有 pi_sync／共享资料流程独立保留。
4. 已有获准资料副本和业务工具继续保留；跨会话个人记忆的目标是自动保存稳定偏好与明确决定，支持更新、查看、纠正和撤回。正式共享记忆尚未上线；计划、推测、AI建议保留身份，生活／学习事实依据本人明确自述。
5. 采用成熟记忆引擎，不从零实现记忆存储、向量检索、抽取与合并算法。当前选 Mem0 OSS 轻量 SDK 服务作为首个试点；这是按现有约束选出的候选，不是已验证可生产部署的结论。详见独立权衡。
6. 用户已取消 Magpie 评估与接入。Chat 保留现有 Router，改进有限模型的选型、上下文与可见性；Work 使用 Alma 原生提供商配置，不新增共用模型网关。
7. PWA 是必须保留的 Dashboard／Overview。Work 信息是可选的只读来源；Work 离线时 Chat 看板继续工作，不扩展为工作派发或远程 shell 控制台。
