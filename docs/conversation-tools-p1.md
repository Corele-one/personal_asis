# P1：持续对话中的受控工具

2026-10-19，checkout实现。本轮继续使用默认Pi原生对话入口，不部署或重启Mac／VPS／AstrBot，不增加Token额度，不扩展来源或账户权限。前一轮P0及原生界面验收保持其历史范围。

## 现在如何使用

```sh
pi
pi --continue
```

直接说问题。普通聊天仍由单一主Agent回答；需要时由模型选择工具，不要求每条消息先填角色／来源／请求编号。

- “从我的笔记找缓存一致性的依据”：调用获准的本机检索，可改词补查。
- “找Folo缓存里作者对这个问题的观点”：只检索已获模型许可的本机阅读正文，保留作者／批注归属。
- “搜索最新相关资料”：模型提出具体公开词；界面显示提供商、查询、结果数、时间范围及资源边界，回复“同意”后执行，或回复“不同意”取消。`/approve`、`/deny`为可选等价控制。
- “请研究角色进一步核对”：可提议一次专业工作，确认后才复用旧角色／WorkStore执行器；不为普通问题默认分工，也不启动后台。

公开查询每次逐项确认。模型可能根据资料提出补查词，但工具正文、先前确认或一般资料访问许可都不能代替本轮新查询的确认。暂不接受“以后所有查询都同意”的无限授权。确认有效15分钟；取消／过期后不会继续请求。用户可用`/new`转到新会话，未完成的旧轮次保留状态，不自动执行。

新默认客户端调用`conversation_tools.submit`；低层`conversation.send`默认仍保留P0协议，已存在轮次始终按保存协议恢复。`pi --engine legacy`保留旧工作入口。简单文本客户端`scripts/asis chat`共享同一Core和会话。

## 版本化工具接口

新增`tool_registry.py`，以冻结的`conversation-tools-v1`注册主机处理器及参数schema；每个工具单独版本化，状态保存manifest指纹。模型只能提出JSON工具动作，不能注册工具、指定Python处理器、扩展权限或改变限额。未知工具、额外参数、布尔值冒充整数及越界参数均拒绝。

| 工具 | 当前能力 | 权限与资源 |
|---|---|---|
| `search_notes` v1 | 既有本机lexical检索，允许缩小sources；沿用提供商许可／排除项／原文版本与位置校验 | 每轮本地检索共2次；只可缩小到当前已授权来源 |
| `search_reading` v1 | WUCAI、Folo、小红书本机阅读缓存检索 | 与search_notes共用2次；需独立模型许可；不访问实时账户，不新建订阅、不获取凭据 |
| `search_web` v1 | 提议公开query，确认后经既有DeepSeek或Exa适配器发现URL | 2次／轮，每次1–3结果；精确query、backend、结果数及recency绑定确认；不自动切后端 |
| `fetch_web` v1 | 阅读本轮已批准搜索返回的URL；沿用本机HTTPS／DNS／跳转校验与有界静态读取 | 2次／轮，单次200–800字符；查询授权仍在有效期；不能读取任意URL或账户内容 |
| `consult_specialist` v1 | 确认后在WorkStore建立一次Research／Career／Life工作，调用旧执行器 | 1次／轮，专业生成最多2次，来源及根目录身份绑定；未完成保留工作，不自动续做 |

公开搜索默认提议现有DeepSeek后端；用户也可要求Exa。供应商价格／实际外部费用未知时明确标注，以操作次数、时间、内容量约束；不把免费MCP、零价UI模型占位或Token预算当作已核对外部账单。没有新增外部消费额度或自动付费重试策略。

模型协议为`chat-tools-v1`，仍由Pi 1.2.0负责循环。模型输出JSON动作，宿主验证后执行；从工具输出直接生成shell、任意URL读取、修改原资料及平台写操作均未开放。Pi UI只是客户端，不持有规划／授权／状态权威。

## 上下文、检索质量与证据

普通聊天仍1次模型、0工具，不预热语义模型或创建Work。每轮最多6次主模型、6次工具动作；专业工作另最多2次生成，全部共享现有日／月账本。新步骤在180秒执行时限内启动；在途模型另有60秒timeout，网络工具还有90秒累计时间预算及请求前预留。暂停等待确认不自动产生调用。

模型工具上下文使用版本化的确定性投影：编号证据每段最多400 UTF-8字节、搜索摘要不再重复送入后续模型、专业暂定判断最多500字节；本机仍保存原始工具快照。历史最多4轮／2800字节，必要时继续裁剪最早历史，完整提示和生成仍受原配置上限约束。没有新增付费摘要或无限历史注入。预算达到80%提示，耗尽前停止新调用。

本轮没有替换既有检索排序或启用V2.3／reranker：

- 从原用户问题冻结可识别的时间范围；模型换检索词不能扩大到时间窗外或未知日期。
- 可按工具参数缩小来源，不能扩大已有来源／模型许可。
- 保留`reading_source`与`reading_attribution`，区分作者原文、用户划线与批注；元数据不冒充完整正文。
- 无命中、源不可用、公开读取失败均返回有界失败回执，让模型报告缺口；不把失败当作当前事实。
- `search_web`只产生发现线索，不能获得E引用；`fetch_web`本机验证后才产生`public_web`编号证据，注明部分正文、抓取时间及来源报告的发布日期。
- 网页快照1小时后失效；个人来源撤权／删除／版本变化、阅读缓存失效或专业工作撤销，均传递清除依赖轮次。已确认个人事实与暂定模型分析仍分开。

日期、归属、撤权与无证据行为已有可重复合成检查，不能据此宣称完整Retrieval Quality Gate、真实个人领域答案忠实性或因果判断通过。P0真实语义缺陷与旧Gate限制继续保留。

## 确认、恢复与审计

新增状态`waiting_permission`保存具体预览及scope hash。确认由本机Core处理，独立于模型关键词路由；只有当前待确认动作下的明确“同意／确认／允许／可以”或`/approve`才生效。没有待确认动作时普通肯定回复仍是聊天，`/approve`不会触发模型。

确认事件另存`conversation_controls`（ID、所属会话、目标轮次、approve/deny、scope hash、时间），不复制私人消息。确认绑定当前会话／动作／参数／提供商／资源上限／15分钟期限；新查询、来源范围或根目录身份变化后重新展示。它是工具范围授权，不是外部写操作Confirmation，也不改写PA1来源政策。

已有模型步骤重放时逐步核对原payload指纹，不因确认后的权限状态变化重新构造已付费提示。确认后继续同一Turn／Run，新增费用只计本次实际新步骤；UI不会因确认或重复查看把之前已付费的Token再次累加。确认事件防重，重复或冲突ID不能建立第二笔调用。

外部搜索、读取与专业工作均在发起前持久化started标记，调用身份防重。若进程在结果返回／计费后而工具提交前中断，恢复时不再请求该操作，返回结果不可重试的回执；模型只能说明缺口或提出另一个需确认的调查。已知失败与未知结果均不自动重试，未知模型继续保留Token预留。完整账务以共享账本为准，外部供应商金额仍标未知。

`conversation-v1`会话容器保留；P0 `chat-json-actions-v1`与P1 `chat-tools-v1`各自分派，旧Agent／agent-web v1–v3及旧角色输入不改。新工具协议需新版本并保留旧恢复实现，不能仅改manifest后重算旧付费步骤。回退到P0／legacy时保留会话库、控制事件、外部调用标记、WorkStore及共享账本；不用删除状态规避防重。
