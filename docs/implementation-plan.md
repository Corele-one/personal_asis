# Personal Agent 实施计划

状态：用户于 2026-10-14 明确选择仅用 Mac 检索，停用 ROG 节点。当前交付范围收敛为 Mac、VPS、PWA 和飞书；ROG 的既有索引／原文件／加密备份保留，后台及开机任务停用。历史双节点验收记录保留，不再以 ROG 日常维护作为 PA0 前提。见 [Mac 单节点运行](pa0-mac-only.md)。

依据：[总规格](../SPECIFICATION.md)、[确认的架构基线](agent-architecture-review.md)、[信息来源方案](information-sources.md)、[框架验证计划](agent-runtime-validation.md)。以下编号是工程步骤，不重新定义 PA0–PA5。

## 1. 补齐 PA0

1. 定义任务、节点心跳、搜索结果、版本和副本的协调协议，实现任务排队、领取、防重、等待与结果补全。
2. 在 VPS 独立部署低敏感协调服务。用户已确认飞书机器人由现有 AstrBot 承载，按 [传输边界](pa0-feishu.md) 复用其飞书 socket 入口，仅执行受限 PA0 插件，不进入 AstrBot 模型流程。VPS 只保存获准状态和元数据。
3. 实现节点配对、系统凭据库保存、短期凭据刷新和 HTTPS 校验；Mac 通过出站轮询接任务，接入现有 launchd 与索引核对。
4. 完成 PWA 强用户认证和状态／证据界面；实现满足原文不在 VPS 持久化要求的证据传输。飞书校验平台签名与用户白名单，输出仅限获准搜索摘要。
5. ROG WSL 同协议节点、systemd 用户服务和 Windows 凭据管理器已部署；先用隔离合成来源验证，再接入四个 Windows 根目录，现已索引 879 Markdown 及 2,430 PDF／Office 文本，仍采用精确远程白名单。
6. 按总规格七项 PA0 验收逐条演示，补真实休眠／唤醒和恢复验证。备份目标及用户持有密钥配置后完成加密状态备份与恢复演练，作为上线恢复准备。

已完成的 Mac FTS5、UUID／版本、保守移动识别、副本分组、来源权限和 CLI 保留复用。单机模拟不替代 Mac／ROG 实际联调。

## 2. 建立业务状态与验证 Pi

本机 SQLite 承担需要事务保证的委托、运行、进度、工具执行、预算和审计状态。定义角色／委托／运行／会话的关联，以及暂停、取消、恢复和结果未知的表示；执行框架通过适配接口读写获准状态，不成为权限或用户任务的唯一权威。

先用合成资料与模拟领域工具，按 [验证计划](agent-runtime-validation.md)评估 Pi 组件：工具循环、权限执行、披露过滤、总管路由、有限并行、同账号排队、主动请求优先和原节点恢复。交付适配接口、组件比较和可复查的运行结果，再固定组件与版本并记录有实质取舍的决定。

模拟通过不等于 MiMo 兼容，也不等于真正隔离已部署；通用脚本、网络和工具端口的执行边界需要实际核验。

## 3. 逐个接入信息来源

推荐先交付 WUCAI 官方读取接口和 Folo 官方 CLI，再接知乎官方 CLI、小红书指定 MCP；公众号利用剪藏、分享和已有可用订阅，暂不另建全量更新爬取。每个适配器独立降级，失败或部分覆盖明确返回。

统一读取结果保留原文出处、平台身份、内容版本、获取时间、正文／摘要／媒体链接状态和到达渠道；作者原文、用户批注、用户手选与 Agent 代选分开。同文多渠道到达不冒充多份独立证据。

Folo 全订阅按委托主题筛选；个人精选尽量回溯可获取历史，订阅流主要增量获取。相关正文缓存 30 天，精选长期可检索；到期清理同时核对全文索引，引用的最小证据按独立审计政策保留。小红书的可见收藏和知乎关注内容必须现场测覆盖，不能以项目功能列表承诺全量历史。

账号区域、凭据、读取范围和分类规则在各适配器启用前配置。读取不自动标记已读、收藏、点赞、发帖或更改平台内容；登录态、私人订阅与来源全文留在获准本机。

## 4. 接入本机检索与 MiMo

为新来源增加可检索的文本适配，在现有精确／全文检索上加入本机语义检索，支持独立降级。按当前工作构建最小上下文，保留证据版本与来源定位；检查来源和提供商权限后，由一个获准在线本机节点直接调用 MiMo。

部署前核验实际端点、模型、工具调用能力与价格，配置 Keychain 凭据和费用上限，先用合成资料完成有限真实调用。实现结构化输出、预算核对、超时／失败／结果未知处理，再验证真实获准阅读材料。

普通文章与非敏感批注可进入相关最小上下文；私密、健康资料仍受原有限制，不能先上传给云模型判定敏感性。能力不足时返回限制；不要假定 MiMo 支持图片或声音。

## 5. 交付总管与三个专业角色

正式的首个 Agent 版本保有四个角色，按需运行。总管围绕委托规划、分配工作并汇总，专业角色的跨领域请求经总管路由；每个领域保有已确认目标／约束及按委托组织的工作记录，执行时检索相关历史。

先打通可反复使用的“获准来源发现 → 结合个人精选／笔记 → 分析研究或申请问题 → 输出带证据的建议”流程。独立工作有限并行、共用预算，同账号浏览器操作排队。主动请求先返回理解与计划，取得证据后给初步成果，持续补全并明确完成状态。

申请比较查验当轮官方要求和日期。生活角色先交付获准记录、检索、本机统计与可复核回顾；私密模型分析需另有可用本机处理路径，不能因角色存在而上传 journal。飞书饮食／作息采集属于独立领域试点，需可靠落盘、加密离线队列及事件去重；照片识别另需经过验证并获授权的视觉适配器。

## 6. 持续运行与自动代选

为每项启用的委托配置主题、获准来源、触发／频率上下限、到期与停止条件、预算和通知规则。实现增量领取、动态频率、主动请求容量预留、后台延期、普通成果汇总和需介入／到期风险／持续失败提醒。

“停止这项工作”暂停整项委托及子工作，保存成果，等待明确恢复；原节点离线后继续等待，不自动迁移。代选仅在用户认可的条件和数量上限内运行，记录代选理由、规则与出处；移除当前精选后允许以后再次合规选入，但不能恢复已被撤销的来源权限。

用真实运行观察验证恢复、费用和噪声控制，再扩大来源或并行容量；具体数值作为可见配置，不由模型擅自扩大。

## 7. 后续能力按切片增加

- **PA2**：从结果中提取行动候选，用户确认后成为正式任务。
- **PA3**：把确认的时间安排投射到日历，逐项确认并防重复写入。
- **PA4**：可读长期记忆、规则候选及复核；角色工作上下文不自动变成永久个人事实。
- **能力注册增强**：成功脚本／流程形成版本候选，经验证和用户确认后注册，附依赖／调用关系、权限和回退方式；不自动授权对外写操作。
- **PA5**：持续收信、关联历史、生成草稿，发送仍需精确确认与防重。

上述切片不把生活记录和申请分析推迟到邮箱实现之后，也不改变 PA0 的纯文本和无模型验收范围。

PDF／Office、双设备副本、加密阅读与 ROG 备份恢复能力已实现并留档。用户随后明确缩减为 Mac 单节点日常检索；当前任务是停用 ROG 并验证新旧搜索不再等待它，不继续追加 ROG 整理／维护或要求用户完成 F 盘备份传输。Mac 本机备份已恢复验证，额外跨机器副本尚未完成。详见 [单节点运行](pa0-mac-only.md)。
