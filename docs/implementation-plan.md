## 3. 逐个接入信息来源

推荐先交付 WUCAI 官方读取接口和 Folo 官方 CLI，再接知乎官方 CLI、小红书指定 MCP；公众号利用剪藏、分享和已有可用订阅，暂不另建全量更新爬取。每个适配器独立降级，失败或部分覆盖明确返回。

统一读取结果保留原文出处、平台身份、内容版本、获取时间、正文／摘要／媒体链接状态和到达渠道；作者原文、用户批注、用户手选与 Agent 代选分开。同文多渠道到达不冒充多份独立证据。

Folo 全订阅按委托主题筛选；个人精选尽量回溯可获取历史，订阅流主要增量获取。相关正文缓存 30 天，精选长期可检索；到期清理同时核对全文索引，引用的最小证据按独立审计政策保留。小红书的可见收藏和知乎关注内容必须现场测覆盖，不能以项目功能列表承诺全量历史。

账号区域、凭据、读取范围和分类规则在各适配器启用前配置。读取不自动标记已读、收藏、点赞、发帖或更改平台内容；登录态、私人订阅与来源全文留在获准本机。

## 4. 接入本机检索与 MiMo

为新来源增加可检索的文本适配，在现有精确／全文检索上加入本机语义检索，支持独立降级。按当前工作构建最小上下文，保留证据版本与来源定位；检查来源和提供商权限后，由一个获准在线本机节点直接调用 MiMo。

部署前核验实际端点、模型、工具调用能力与价格，配置 Keychain 凭据和费用上限，先用合成资料完成有限真实调用。实现结构化输出、预算核对、超时／失败／结果未知处理，再验证真实获准阅读材料。

普通文章与非敏感批注可进入相关最小上下文；Study／Life 的现有及新增私密资料已获用户持续授权，可经 MiMo Flash 按需分析。其他私密来源默认拒绝，不能先上传给未获准云模型判定敏感性。能力不足时返回限制；不要假定 MiMo 支持图片或声音。

## 5. 交付总管与三个专业角色

2026-10-15 已实现 [本机领域目标／约束首片](agent-domain-context.md)：显式配置、默认本机保存、单条模型许可、来源绑定、90 天复核、可修改／删除，按需 Agent 显式选择并保持付费恢复协议。新增 11 项合成检查；未自动创建真实个人目标。随后已实现[相关委托历史检索](agent-work-history.md)：显式选用、同领域及来源过滤、旧依据重新核验、固定快照付费恢复和传递失效，新增 13 项合成检查；总管分工和四角色串行运行随后已按[独立切片](agent-roles.md)交付；完整领域上下文及角色并行仍待实现。

正式的首个 Agent 版本保有四个角色，按需运行。总管围绕委托规划、分配工作并汇总，专业角色的跨领域请求经总管路由；每个领域保有已确认目标／约束及按委托组织的工作记录，执行时检索相关历史。

先打通可反复使用的“获准来源发现 → 结合个人精选／笔记 → 分析研究或申请问题 → 输出带证据的建议”流程。独立工作有限并行、共用预算，同账号浏览器操作排队。主动请求先返回理解与计划，取得证据后给初步成果，持续补全并明确完成状态。

申请比较查验当轮官方要求和日期。生活角色先交付获准记录、检索、本机统计与可复核回顾；私密模型分析需独立提供商授权（当前 Study／Life 已授权 MiMo Flash），不能因角色存在而扩大到其他模型、来源或渠道。飞书饮食／作息采集属于独立领域试点，需可靠落盘、加密离线队列及事件去重；照片识别另需经过验证并获授权的视觉适配器。

## 6. 持续运行与自动代选

为每项启用的委托配置主题、获准来源、触发／频率上下限、到期与停止条件、预算和通知规则。实现增量领取、动态频率、主动请求容量预留、后台延期、普通成果汇总和需介入／到期风险／持续失败提醒。

“停止这项工作”暂停整项委托及子工作，保存成果，等待明确恢复；原节点离线后继续等待，不自动迁移。代选仅在用户认可的条件和数量上限内运行，记录代选理由、规则与出处；移除当前精选后允许以后再次合规选入，但不能恢复已被撤销的来源权限。

用真实运行观察验证恢复、费用和噪声控制，再扩大来源或并行容量；具体数值作为可见配置，不由模型擅自扩大。

## 7. 后续能力按切片增加

- **PA2**：从结果中提取行动候选，用户确认后成为正式任务。
- **PA3**：把确认的时间安排投射到日历，逐项确认并防重复写入。
- **PA4**：可读长期记忆、规则候选及复核；角色工作上下文不自动变成永久个人事实。
- **能力注册增强**：成功脚本／流程形成版本候选，经验证和用户确认后注册，附依赖／调用关系、权限和回退方式；不自动授权对外写操作。
- **PA5**：持续收信、关联历史、生成草稿，发送仍需精确确认与防重。

上述切片不把生活记录和申请分析推迟到邮箱实现之后，也不改变 PA0 的纯文本和无模型验收范围。
