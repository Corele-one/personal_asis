## 原因

“总结一下我过去的一周”属于已有授权内的基本个人复盘，失败来自实现缺陷。旧相对时间解析未识别“过去的…”中的“的”，时间窗为空；auto没有识别生活复盘而选择research。模型专业角色返回JSON字符串，内含未转义英文引号，已知返回且已记账，随后JSON解析失败。`model_output_has_invalid_evidence_references:json`中的json表示格式解析失败，本例并非引用编号错误，也没有输出截断证据。状态页把显式空result当成对象，又触发通用终端错误。

原调用为一次、623 Token；保留原响应、账本和步骤，不猜测修补引号、不自动重试，也没有换请求编号重新运行真实问题。私密诊断及模型原文只保留在原私密运行目录。首轮只测了真实问候，验收范围不足以覆盖这种资料复盘。

## 修复行为

本机auto／life的新个人日期复盘使用独立 `local-dated-review-v1` 协议，识别带“的”的相对日期和上周。以2026-10-19为例，过去一周是10-13至10-19，上周是10-12至10-18。已有Life范围时缩至Life；只授予Study时不增加Life。显式research、普通主题总结、远程入口和历史工作保持原协议。

宿主按获准记录日期筛选当前正文，不要求正文含“总结”或“过去一周”等词，也不启动语义模型。权限在读取前及当前内容检查后复核，原位置／哈希／版本校验继续执行；日期未知、冲突、窗外及外部阅读缓存排除，无记录不回退旧材料。无匹配时由本机返回资料不足，零模型调用。

优先每个日期一段，再补片段；最多七段、上下文5400 UTF-8字节。超过五个日期时每段最多160字符，其余最多240字符。原普通角色证据上限六段不变；完整提示8192字节、生成512 Token、日100,000／月1,000,000预算不变。日期复盘一次JSON生成，不调用研究专业角色或额外工具。报告实际找到和选用的记录日期，并明确这是片段覆盖，缺记录不等于无活动，笔记日期不保证活动日期，计划不等于完成。

新本机纯文本专业角色、纯文本最终回答和日期复盘使用提供商既有JSON模式。它只约束输出格式，结构／引用仍须通过原校验，不能保证语义正确。旧付费会话不补字段、不改序列化输入。`/status`与失败恢复能显示静态中文原因；空result不再崩溃，已知JSON失败恢复只诊断、不执行。
