# 在私人看板中纠正记录

普通聊天保存在VPS作为助手记忆；`/life`明确提交的正文才进入日记。看板的生活记录、Habits与Learning旁有“纠正这条”，顶部有“和 Agent 聊聊”。选择具体记录后，可以说明“这是实践作业要求，不是我读过的书，请去掉阅读记录”。对话会保留目标、原始版本和修改回执。

Agent复用本人当前AstrBot会话选择的模型与原生工具循环，仅获得本次选中记录、最近几轮反馈及受限纠正工具。支持清除误判的某项习惯、清除该条学习整理、修正摘要或行为整理、将内容排除出随记。没有选中记录或说明不明确时先核对；不开放文件、shell、平台发送、Mac笔记写入或来源授权修改。

原始消息保持原样。本人这次反馈可以成为新的纠正证据，单独注明反馈来源，不将模型自己生成的话当作本人原话。去掉误判后显示“未记录”，不据此判为本人没做。更新落在同一份VPS生活数据库，Dashboard刷新后可见；已写入Mac原日记的改动仍在下一次`pi_sync`完整预览后确认。

## 执行与恢复

HTTP接口沿用原有HTTPS代理、本人登录会话、SameSite Cookie与CSRF校验。提交请求ID可安全核对重复提交，目标记录和预期版本由界面绑定，模型不能更换记录ID。每次请求最多应用一个纠正动作，并原子保存数据版本与前后回执；并发更新拒绝覆盖。

反馈通过同一私密SQLite中的队列交给既有AstrBot插件，不新增服务端口或主Agent，也不发送飞书测试消息。原生Agent最多4步、工具10秒、整轮90秒。请求开始前持久占位，失败／超时或重启中断标为结果未知，不自动再次调用付费模型；即使最后回复中断，已落盘的纠正回执仍可查看。看板只能显示已保存的工具回执为“记录已更新”。

反馈线程、消息、回执和本人证据都属于私密运行数据（0600），不进入Git或共享整段对话。普通聊天的原始用户消息可继续作为已有共享生活资料中的“对话记忆”，明确区别于日记；不导入AstrBot完整会话或助手历史输出。

## 历史误判

部署前用SQLite备份接口备份原库。历史缺少来源字段时，只凭原始`/life`／SDK去斜线后的`life`前缀识别主动记录；其他聊天补标为对话记忆，原文保留。已误判的作业要求／引用观测撤下，重新输出来源版本；看板和回顾使用经过语境检查的本人行为，日记旧副本的移除仍需本人确认。代码回退不自动覆盖运行数据，备份和已经发送的平台副本分别处理。
