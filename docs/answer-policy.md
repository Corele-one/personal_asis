# 本机回答策略与校验

2026-10-20，checkout 实现，未部署。只调整本机 Conversation 新轮次；原模型、来源许可、工具注册表、共享预算及网络／操作确认不变。

## 已观察的拒答路径

只读检查已有私密 Conversation 记录，未重新调用模型或读取真实资料生成答案；原始响应和正文仍留在私密状态目录。

| 问题 | 实际路径与失败阶段 |
|---|---|
| 周回顾 | 当前消息＋一轮会话 → 模型直接回复，无检索 → JSON 合法但字段为 `status/reason/missing_info`，状态 `need_more_context` → 旧校验在 schema 阶段失败 → CLI 统一显示证据校验失败。该轮没有可用个人证据，也没有冻结日期窗；不能据此归因为引用编号不合法或权限撤销 |
| 主观印象 | 当前消息＋两轮会话 → 一次检索成功，三段证据 → 模型输出合法 JSON、`insufficient_evidence`、无引用 → 旧校验替换为固定拒答。召回不为空；是否足以支持具体历史事实未做语义判定，但缺少历史证据不应阻止有限主观观察 |
| 后续周回顾 | 两条工具回执为 `unavailable/tool_unavailable_or_request_not_retryable`，随后模型弃答；其中一条有日期窗。回执无法区分底层故障，不宣称已定位为权限、索引或网络问题 |

较早 Legacy Agent 的未转义引号问题是另一条历史案例，见原修复记录（旧说明已退役，见[当前规格](../SPECIFICATION.md)），不与本次 schema 失败混同。

## 新轮次的回答策略

新默认为 `chat-tools-v2`，内部策略 `answer-policy-v1`；会话容器仍是 `conversation-v1`。分类是宿主冻结的回答约束，不能授权任何工具。

| 策略 | 行为 |
|---|---|
| Conversation / Reflection | 问候、能力说明、概念和建议可直接回答；印象可用当前消息与实际纳入的本会话给出暂定观察，不强制笔记引用。补上观察范围、可纠正性；不把分析记成个人事实 |
| Personal Recall / Synthesis | 具体经历优先检索，保留原始证据链接；允许带局限的部分综合。引用缺失不会自动否定全部综合，但标记未独立核实，不能伪造个人事实。可访问会话里的用户自述与助手分析分别处理 |
| Verification / Action | 官方日期、申请条件、财务、健康和操作保留来源与严格校验；不能以 `conversational/subjective` 状态规避。指代前一轮核验问题的追问继承该策略。操作仍限冻结工具与原确认流程 |

响应状态区分 `supported`、`partial`、`subjective`、`conversational`、`no_fact`、`tool_unavailable`、`permission_denied`。`insufficient_evidence` 兼容输入转成具体回执；没有事实、无法取得证据、无读取权限分别说明。对印象的无事实弃答只可退到基于当前提问的有限观察，不能保留模型未获支持的经历／性格断言。

`answer` 是自然语言，`answer_metadata` 由宿主附加策略、结果类别、引用归属状态、覆盖、会话范围和禁止自动重试信息。模型仍以小 JSON 对象传输内容，`citations` 和空 `uncertainty` 可省略；本轮没有引入新的自由文本工具协议。

## 日期与会话范围

- 当前消息、本会话有限历史、本轮原始记录、模型暂定推断分别进入 Prompt；历史 E 标签去除，助手历史不作为已确认事实。源证据与后续历史依赖继续重新核验。
- 本会话仍最多四轮／2800 UTF-8 字节，必要时裁剪。跨 Session 历史检索尚未实现，不能声称已使用；没有增加长期记忆或额外模型许可。
- 新解析支持“过去的一个礼拜／过去的一周／一个星期／上周”，冻结 `Asia/Shanghai` 日期窗。例如 2026-10-20 的过去一个礼拜为 10-14 至 10-20（含首尾），上周为 10-12 至 10-18。
- 日期回顾在第一次生成前，由宿主复用既有日期读取器取得授权片段，无需笔记包含“总结”等查询词。最多六段／原5000字节证据限制，保留七段 Legacy 复盘的原默认。仍受完整 Prompt／生成及日月预算约束，不启动语义模型。
- 报告找到与实际选用的记录日期、记录数、片段数；日期未知、冲突或窗外记录不补入。选满所有有记录日期仍只是片段覆盖，不是完整活动清单。无日期记录时不会从无日期的闲聊猜测一周活动。计划、他人叙述和笔记日期归属仍须语义验收。
- 日期上下文保存为独立步骤；中断恢复重放原回执与原模型 payload。宿主读取有实际步骤事件；不因本地格式规范化重查资料或增加模型调用。

## 校验与恢复

| 层 | 处理 |
|---|---|
| Protocol | 供应商 usage／结束原因、工具动作、JSON 对象是否合法；不猜补未转义引号或截断 JSON |
| Safety / Policy | 来源／模型授权、当前版本／原位置、秘密扫描、工具参数与确认、网络边界、费用／未知结果继续由宿主执行；不是 Presentation 降级项 |
| Evidence Attribution | 每个行内和列表编号必须真实存在；核验类必须有回答中的原始出处。合法编号只证明归属，不证明每句话的语义蕴含 |
| Presentation | 从合法行内引用生成列表，排序／去重，移除未展示但合法的冗余列表项；允许省略展示字段。不能补造编号，未知编号即使只在列表中也拒绝 |

无法可靠修复时保留 `failed` 和已付费模型步骤，`/status` 返回 `validation_error.layer/reason/recovery`；CLI 区分 JSON、字段、引用归属、敏感内容。不会为了修格式自动再次付费。可本地诊断、补充上下文另开明确新问题；失败轮次不开放自动重跑。已保存步骤不等于已经展示未校验正文。

旧 P0、`chat-tools-v1`、Legacy Agent、WorkStore 与 web v1–v3 保留原校验及序列化路径；不改写已完成答案或历史验收，不迁移账本。回退时将新提交入口指定为 `chat-tools-v1`；保留 v2 恢复实现和所有私密状态／防重标记，不删除数据库来回退。

正确性保护另外验证不存在的引用、无记录虚构事实、来源删除／撤权、旧付费／新付费检查点重放，不能只凭拒答减少宣布质量提升。真实模型平均 Token、事实正确率、计划／日期／归属忠实性和真实 Pi UI 仍未验收；下一步是在现有预算内，用少量明确获准问题做人工事实标注与单次生成评测。工具不可用的两条历史记录缺少底层分类，本轮不能追溯补证；不自动重放它们。
