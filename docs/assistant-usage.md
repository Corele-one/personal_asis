# 综合个人助手：使用与运行

本轮按用户选择，交付研究、申请职业、生活复盘都可按需使用的版本。线上入口为 [个人助手控制台](https://35.209.202.207/)，本人飞书沿用已绑定私聊。四角色的实现与验收见[协作说明](agent-roles.md)和[脱敏验收记录](validation/agent-roles-20261015.json)。

## 从控制台开始

登录后找到「个人助手」，选择本次资料范围及工作方式，输入问题并开始。工作方式可选总管自动分工、知识研究、申请与职业、生活记录与复盘，或三个领域共同分析，也可选择「倾听与鼓励（不读笔记）」。Study + Life 是明确选择两个已有来源；角色选择本身不授予任何资料权限。

| 工作 | 建议资料与工作方式 | 问题示例 |
|---|---|---|
| 倾听与鼓励 | 任意已有范围／倾听与鼓励（不读笔记） | 合成示例：今天做实验有点累，给我两句鼓励。 |
| 学习与研究 | Study／知识研究 | 根据这些资料比较两个机制，分别列出直接证据、推断和需要补查的地方。 |
| 研究生申请与职业 | Study，必要时显式加入 Life／申请与职业 | 结合我的现有材料，比较准备方向，列出已记录的经历、缺少的材料及待我选择的建议。 |
| 生活复盘 | Life／生活记录与复盘 | 复核最近相关记录，区分我的自述与暂定解释；缺少的记录单独列出，不作诊断。 |
| 跨领域问题 | Study + Life／总管自动分工或三个领域共同分析 | 比较申请准备与生活约束，列出证据支持的冲突、未知项和可供我选择的下一步。 |

简单安慰／鼓励请求在自动或生活方式下直接回应本轮消息，不先翻历史。明确要求结合记录时才走相应检索流程；建议写清「最近七天」等范围。卡片会区分 Agent 的回答与历史原文并显示笔记日期，详见[回应与时间范围](agent-response-routing.md)。

每次只检索部分相关资料，不能由一次检索宣称覆盖全部日记或准确统计一段时期。申请的当轮官方要求和日期应使用「结合资料分析 → 按需公开研究」，显式提供公开检索词和官方 HTTPS 链接；本轮角色工具只有本机检索，不会自动联网验证政策。没有相应证据时应报告缺口。

保存页面中的工作编号。查看状态不调用模型；暂停阻止后续步骤，恢复沿用原工作、来源、计划及已付费步骤，取消后不能恢复。修改问题、来源或角色时新建工作，不能沿用已付费编号改变协议。关闭页面、清除此页或 Mac 休眠不会取消已发出的模型调用。

## 领域目标与继续工作

飞书 `/asis → 管理领域目标`，或 PWA「个人助手 → 管理领域目标」，可先查看再保存／替换／删除目标及约束，不调用模型。新问题可选「采用各角色已保存的目标」或「采用各角色目标和相关工作历史」。每个专业角色只使用自己的目标和先前判断；卡片显示本次是否采用及历史数量。目标的适用来源需覆盖本次全部来源，未获准或待复核会显示未采用。简单倾听仍只看本轮消息。详细边界见[连续性说明](agent-role-continuity.md)。

## 本人飞书

发送 `/asis` 打开[交互卡片](feishu-cards.md)，直接选择工作方式、资料范围并填写问题；结果和控制按钮在原卡片中更新。以下文字命令也可继续使用。

```text
/asis agent life conversation | 合成示例：今天实验有点累，给我两句鼓励。
/asis agent study research | 根据材料解释机制差异，逐项附证据并列出未知。
/asis agent study career | 根据现有经历和目标，列出申请准备材料及缺口。
/asis agent life life | 区分相关记录中的自述与暂定解释，不作诊断。
/asis agent study,life auto | 综合申请准备与生活约束，提出供我选择的下一步。
/asis agent study,life team | 请三个领域分别核对这个问题，再给出有证据的汇总。
/asis agent-status 工作编号
/asis pause 工作编号
/asis resume 工作编号
/asis cancel 工作编号
```

原来不带角色的 `/asis agent study | 问题` 保留直接检索分析流程。群聊、未绑定用户及其他传输入口拒绝处理。飞书可收到相关最小摘录，平台会接触回复；VPS 只持久保存投递路由与防重身份。完整飞书往返的本轮真人验收仍由用户完成，SDK 合成发送测试不能替代真实平台回显。

## 模型、在线条件与边界

现有模型仍为 MiMo Flash，共享预算为每日 100,000／每月 1,000,000 Token。每次协作最多三个专业判断、六轮总管调用、三次本机检索和六条证据；先串行执行专业角色，总管再核对汇总。角色更多会增加用量，不会增加预算。格式或引用不合规的结果不展示，实际用量照实记账；结果未知的调用不自动重做。

Mac 保存原资料、索引、权限、工作和预算；服务器提供协调、PWA 与飞书入口。Mac 在线且 SSH 隧道正常时才能分析，离线时保留工作编号等待原节点。服务重启后需明确恢复未完成的按需工作；本轮没有启用自动后台委托。维护见[Mac 单节点运行](pa0-mac-only.md)。

当前可按需检索、阅读、分析、受控角色协作和恢复；已有专业角色领域目标／相关历史及本人渠道管理。自动长期记忆、后台订阅／委托、平台收藏来源接入、餐食照片识别与作息采集、正式任务、日历及邮件仍未交付。这个版本不会替用户创建正式任务或向第三方发送内容，也不自动改变来源权限。
