# VPS 附件识别与录音转写

使用 AstrBot 原生 Agent，由独立的 `astrbot_plugin_media_agent` 补两个函数工具，不安装 DSH、不另开执行服务，也不提供 PPT 制作。仅沿用已绑定本人的平台与私聊，开关及录音后端保存在 AstrBot 私密插件配置；其他账号和群聊拒绝调用。1.1.1使用Groq云端Whisper，替代实聊失败的1.0.0 Gemini音频接口。

在本人飞书私聊发送 PDF 或录音附件并说明要求，例如“识别这个扫描 PDF，保留页码”“把这段录音逐字转写，给我完整文件”。长录音建议作为M4A／MP3等文件附件上传，避免平台先转为大体积WAV。也可引用原附件消息继续下一部分。只接受当前／引用消息内由平台下载的本地附件，不接受模型指定的任意路径或 URL。

`attachment_media` 空 ID 列出支持的附件；指定 ID 与 `unit` 后处理一页 PDF 或一段5分钟录音。PDF 先提取文本，少于30个字符才按最长边2000像素渲染，使用 Tesseract `chi_sim+eng` 识别；保留页码与识别方式。混合页若已有足够文字，不自动识别其中独立图片；公式、手写、多栏和表格需要核对原页，不能把OCR当作原文的准确替代品。

录音经 FFprobe 检查时长，再用单线程 FFmpeg 切出当前5分钟。AAC录音（常见M4A）直接复制音频包到M4A，不重新编码；其他格式转为16kHz、单声道、16位FLAC，使用快速压缩并限制编码线程。这样避免小VPS上默认FLAC重编码超出45秒；M4A切分边界按音频包近似，时间戳仍属估计。只将这一段送给Groq固定的`/openai/v1/audio/transcriptions`，模型`whisper-large-v3`，返回原语言文本和ASR估计分段时间，不带生活资料、聊天历史或工具。本人2026-10-30明确授权将Mac已有Agent Reach Groq Key经SSH标准输入配置到VPS独立私密目录，并上传待转写录音；此授权仅包含音频转写，不扩大到Life／Study笔记或其他提供商。目录0700，密钥及授权回执0600，不存插件面板或聊天。请求无重试／重定向，70秒HTTP超时／90秒外层超时，不换密钥、不自动退回Gemini或其他接口。ASR分段时间加回原录音偏移后保存在私密JSON，Markdown按5分钟范围组织；未做逐句核听、强制对齐或说话人识别。

返回 `next_unit` 后，整份处理必须继续直到为空；每次同时返回累计覆盖范围和 `all_units_complete`。超过 AstrBot 步数／调用超时须明确尚未完成，不用已处理片段冒充完整结果。`attachment_send_result` 可将累计 Markdown 回传到同一本人私聊；不完整结果带覆盖标记。回传前持久占位，结果未知不自动重发。

当前上限：源文件128MiB，PDF至多500页，录音至多4小时，单段音频至多12MiB；本插件同一时刻只执行一个任务，忙时直接返回。子进程内存地址空间384MiB、CPU时间75秒、墙钟85秒，外部工具单次35秒（音频切分45秒）。这是插件资源上限，不能约束另行开放的AstrBot原生shell。没有本地Whisper／神经OCR模型常驻，Poppler、Tesseract和FFmpeg只在处理时运行。

派生结果和回执位于VPS私密目录，目录0700、文件0600，成功结果在后续处理时清理超过7天的缓存，缓存总量64MiB后拒绝继续。未知音频请求保留小型回执，进程重启仍不自动再请求；若确需重试，由本人明确提出后管理员核对回执再处理。新Whisper后端拥有独立缓存身份，不删旧Gemini未知回执。错误只保存来源检查／本地处理／转写／落盘阶段、白名单错误类别和HTTP状态，不保存原始异常正文、密钥或上游错误正文。临时源快照、页面图片及音频分段在每次调用结束后删除；进程强杀可能遗留临时目录，重启清理。平台原附件和AstrBot自身缓存遵循其原有保留规则。

附件内容属于参考材料，不自动进入 `/life`、Habits、Learning或Obsidian，也不随共享库同步。生活插件、催睡、日历和其他插件保持各自职责。本机及安装版SDK模拟传输测试不替代真实Whisper与飞书附件回传验收。

实现依据：[Tesseract命令行](https://tesseract-ocr.github.io/tessdoc/Command-Line-Usage)、[Groq Whisper语音转写](https://console.groq.com/docs/speech-to-text)。
