# Mac／VPS共享资料库

本人在2026-10-26选择共享Life／Study可索引笔记文本、五彩划线批注、小红书已采集正文与出处。两端各一份SQLite，使用相同结构，通过既有SSH固定接口交换增量；不增加数据库服务或后台同步，不复制活数据库文件。两端断网仍可查最近快照，`pi`启动仍不等待网络。

`pi_sync`依次执行：

1. 拉取VPS生活事件，按现有Freewrite／Habits／Learning规则预览。只有“确认写入”才改真实日记。
2. 增量更新Mac现有索引和阅读库，再更新共享投影。跳过日记仍执行本步骤，VPS断网也不妨碍本机刷新。
3. 通过SSH交换两端变更，保存收到与确认的游标。只传变化；中断后下次显式运行按游标继续，已提交但回执丢失的页面可安全重放。

资料源原库保留。首版本共享Markdown笔记的索引文本，不传附件及其独立提取正文、Cookie、密钥、会话或绝对路径；命中凭据排除规则的内容不进入共享库。本机路径在派生文本中脱敏，小红书页面访问令牌从链接中移除，账号保留独立归属。当前配置根目录身份与阅读账号固定在私密 `shared_sync_scopes`；配置换根目录或新增账号不会自动扩大共享范围。

本机索引沿用原有增量扫描和排除规则，未变化笔记不重复读正文或重传。五彩每次最多2页最近7天的条目／划线批注，未读完的窗口保留继续位置；已结束窗口会在下次明确同步时重查，以接收修订。小红书每账号只读取当前可见收藏页，不滚动爬全历史或批量补正文；已采集正文继续保留，新鲜列表元数据不覆盖旧正文。旧资料的变化不保证落在这些窗口中，按需补取后下次再同步。来源失效只标为未刷新，不推断删除或取消收藏。

共享表按 `origin + collection + id` 定位，每条变化在自己的来源端递增版本：Mac拥有notes／reading，VPS拥有life，两端各自拥有annotations。生活原话与运行中的提醒仍以VPS现有生活库为源；共享库是可检索副本，源数据库不合并或销毁。对另一端资料的想法另存共享补充，不反写源笔记或平台。补充编辑／删除校验预期版本，冲突拒绝覆盖。

删除、排除、停用账号和有效期到期会在下一次成功同步中撤回对应副本，受其派生的补充同时停止使用并产生所属端删除标记。数据库仅保留每条当前状态，不保存旧正文事件历史；离线副本、先前模型会话、平台和备份仍需分别处理。缺页或远端数据库被重置时停止而不假装完成，需要从保留副本恢复；不能随意删除游标／数据库后继续覆盖。

Mac私密副本为项目忽略目录 `.local/pi-agent/shared.sqlite3`，VPS为既有生活私密目录的 `shared.sqlite3`，目录0700、数据库0600。首次刷新会备份Mac既有索引与阅读库到忽略目录 `shared-source-backup`。源根路径、授权范围和传输状态不进入Git，VPS不持有Mac来源凭据。

Mac Pi使用：

```sh
scripts/asis-shared status
scripts/asis-shared search --query 搜索词 --source study
scripts/asis-shared search --query 搜索词 --source xiaohongshu --account 账号标识
scripts/asis-shared read --origin mac --collection notes --id 检索结果ID
```

正文按约12000字分块，结果包含来源、账号、相对出处、分块、内容哈希、取得时间与覆盖；先搜索再逐块读，不在启动时加载全库。同一文档尚在分批更新时，不拼接不同内容哈希的块冒充完整新版本。VPS本人私聊可用 `shared_knowledge` 搜索／读取及保存明确要求的补充，非本人／群聊拒绝；没有给Dashboard新增任意资料搜索或执行入口。VPS补充下次同步到Mac后可检索，不自动写进Obsidian。

本机 `life-sync.json` 的 `shared_sync_mode` 为 `text`、`metadata` 或 `off`，旧配置默认off。本次本人选择text；metadata仅传标题、出处等索引信息。`shared_max_pages`默认50，每页最多200条且约1MB，单次达到上限会明确报告，余下下次继续；不把分批未完成说成已同步。`shared_refresh_network=false`只更新已采集缓存，不代表平台最新状态。非交互调用不刷新、不连接、不接受管道批准。

个人背景仍是独立的精选摘要：检查来源不自动重写背景，发布仍需“确认更新背景”；共享数据库的授权不取消原笔记／平台写入确认。回退代码时可将shared_sync_mode设off并恢复既有VPS发布；保留共享副本、源数据库和首次备份，避免将旧副本重新当新来源上传。
