## 范围与控制

2026-10-18 现状：生产及默认 AgentHost／search_notes 仍使用原 ContextBundle 与证据上限，专业角色不能独立检索。`/asis retrieve-v2` 是独立只读 action。新 checkout 另有显式实验 [agent-web-v1](web-search-integration.md)，实际 Pi＋模拟 Provider 已覆盖 V2 本地检索、Exa搜索→正文→网页 Evidence→带引用回答；尚未真实联网／MiMo联调或部署，不替换旧协议。旧 TOOLS、PA1 settings、序列化与已付费指纹不变，完整质量 Gate 仍待通过。

默认及历史协议只有一个 `search_notes(query)` 只读领域工具。用户明确指定来源 ID；模型只能在这些来源中改变检索词，不能增加来源、提供商、预算或工具。检索使用现有 PA1 `build_bundle`，因此沿用独立的私密模型许可、根目录绑定、凭据／排除规则、原文版本和位置校验，以及可选的本机离线语义模型。工具回复只包含当前相关的编号、标题和最小正文，不外发绝对 URI、未授权条目的标题／路径／正文或全量索引。

显式新会话 `scripts/asis-agent run --web --public-query '可公开关键词' --query '问题' --request-id NEW_ID` 使用三工具；加 `--source study` 才允许读取该个人来源，不加时仅公开范围。公开查询必须精确匹配白名单且通过本机隐私规则，网页只能读本工作搜索所得 URL。搜索2次／正文3次／本地3次／网络90秒，沿原 MiMo预算；本地与公开证据分别校验。恢复仅用 `resume --request-id NEW_ID` 自动复用保存的工具、白名单和回执；不能把旧编号升级为新协议。该版本暂不支持领域目标、专业角色、历史或 bootstrap，普通无检索意图可用 `--mode conversation`。详细接口、限制、费用未知记录与回退见[联网集成](web-search-integration.md)。

每次模型请求、工具执行、历史复用和成果返回前，都检查运行租约、当前 PA1 启用状态／配置、来源根目录及已用证据。正文变化或撤权时停止复用并清除该委托的会话、检查点和成果；已有模型／外部平台副本不声称可以撤回。PA1 撤权／核对清理入口已接入会话清理，`work show` 也先清理无效的 Agent 成果。续验发布已将该逻辑接入既有 Mac 核对服务的启动／唤醒／六小时清理路径；本机每次执行、复用或查看仍先检查，不能以核对周期代替下一次使用前的撤权检查。整机重启及新版服务无人值守休眠恢复仍未验收。

Pi 负责模型／工具循环；Python 保有权限、预算、原始资料和状态。MiMo 凭据只由 Python 从现有 Keychain 服务读取，不交给 Node。使用既有端点、Flash、thinking 关闭、`tool_choice=auto`，不注册厂商联网搜索。旧 PA1 分析适配器保持原行为，新增 `ToolMiMo` 单次超时为 60 秒，沿用无重定向／无环境代理／无自动重试。

工具协议依据 [MiMo 官方接口](https://mimo.mi.com/docs/en-US/api/chat)核查；官方 [Flash 模型页](https://mimo.mi.com/models/en-US/mimo-v2.6-flash)列出工具能力及按量价格（本轮核查：每百万输入缓存未命中 ¥1、命中 ¥0.02、输出 ¥2）。这不代表本账户套餐／实际费用已核验，也不代替真实工具闭环验收；未切换模型、套餐或预算。

每次新模型调用先预留「消息和工具声明 UTF-8 字节数＋1,024＋完成 Token 上限」，再按服务端用量结算；使用已有 `pa1.sqlite3`，与所有 PA1 调用共享日 100,000／月 1,000,000 上限。达到上限时保留普通本地搜索／bundle 能力。收到已知输出后，即使格式错误、暂停或撤权也结算实际用量；网络或响应未知则保留预留额。HTTP 错误正文最多在 RAM 读取 8 KiB，只提取白名单的额度／并发／速率等文字信号；它们不是已证实的失败根因。记录 HTTP 状态、合法 Retry-After 和截断类别，不保存错误正文、请求头、请求 URL 或密钥。429／503 在同一节点的共享账本中阻止新调用至少 300 秒，更长的有效提示沿用（最多七天）；冷却后也不自动重试。已完成结果的复用不占新调用；旧的未知预留不因冷却解除而释放。冷却在动作开始前拦住的未尝试请求可由本人在期限过后明确 resume。

每项按需运行累计最多 6 次模型请求、3 次实际检索、6 条证据；检索耗尽时新模型步骤撤去工具声明并要求收尾，仍调用工具则拒绝。旧检查点已保存的超额请求只得到持久化的拒绝回执，不执行额外检索。单轮上下文继续受当前 PA1 `max_prompt_bytes` 和完成上限约束。原节点租约为 15 分钟，整体桥接上限 15 分钟；这是显式请求执行上限，不启用周期调度或主动通知。本页记录原直接执行协议；后续已加入[总管与三个专业角色的串行协作](agent-roles.md)，额外最多三次专业判断。完整领域上下文、角色并行及持续委托仍待交付。没有 shell、通用文件写、浏览器、MCP、动态能力注册或外部写操作，也未宣称操作系统沙箱通过。

## 持久恢复和防重

`work.sqlite3` 新增 `agent_sessions`。每次模型回复或工具结果与动作防重标记在同一个 SQLite 事务内提交，然后才交给 Pi 继续。恢复时从原问题重建 Pi 对话：逐步复用已提交结果，并核对输入指纹；已完成的模型步骤不再次调用模型，已完成的检索不重复执行。每次复用仍重新验证当前来源和原文，保存历史不代表永久许可。工具结果在模型消息中是 JSON 文本，恢复须保留原字段顺序；只对存储对象排序不能改变已付费输入指纹。新步骤的只收尾模式独立保存，见 [ADR 0034](adr/0034-preserve-provider-visible-serialization-for-paid-step-replay.md)。

计费账本与会话库是两份独立事务。若进程在已结算计费、尚未提交回复时退出，动作保持未知，恢复不得重复调用；模拟检查覆盖了这个窗口。进程领取过期、暂停和取消使旧代次不能再提交。未知动作需人工核对，不能通过更换代次重做；即使 `work resolve` 确认结果，缺少已提交回复仍不能重做原动作。格式拒绝、额度拒绝或已完成但丢失正文也不能以同编号自动重试。

完整会话从建立起保留最多 30 天；到期或显式 `clear-results` 后清除正文和成果、保留最小动作身份。未知调用不会因清理正文而获得重试资格。普通无正文事件仍为 180 天。已有委托目标／来源范围保留在本机业务记录中，原始来源文件不修改，长期个人记忆未新增。

## 本机命令

需要已配置的 PA1 home、现有 MiMo 凭据和可选 Pi 依赖。仓库根目录安装／验证：

```sh
npm ci --prefix runtime/pi --ignore-scripts --no-audit --no-fund
scripts/asis-agent validate
```

`scripts/asis-agent` 使用已有 `pa1-env` 解释器并设置离线语义加载环境；它运行当前 checkout，不替换生产 launchd 发布包。若需要其他私密数据目录，使用 `ASIS_PYTHON=... scripts/asis --home ... agent ...`。

以下本机入口已通过限定路径验收；开放问题可能需要收窄范围／输出长度，不能把流程通过当作研究结论正确或全库检索充分：

```sh
scripts/asis-agent run --source study --query "请只检索一次缓存一致性，120字内说明证据能否支持结论及局限。" --request-id local-agent-001
scripts/asis-agent status --request-id local-agent-001
scripts/asis-agent provider-status
scripts/asis-agent provider-status --probe  # 仅读取 /models，不发起生成
scripts/asis-agent resume --request-id local-agent-001
```

`run` 需要明确问题、来源和请求编号（最长 96 字符）；同一编号绑定原问题与范围，改变内容会冲突。重复已完成请求只返回仍有效的成果；暂停中的请求不会自动恢复。`resume` 明确恢复原问题／范围，不能同时传新问题或来源。达到 `--steps N` 个新提交步骤时返回 `checkpointed` 并退出，可在另一个进程使用 `resume`；已提交步骤的复用不占这次 N。暂停／取消仍使用 [work 命令](agent-runtime-local.md)。`status` 只读状态和有效结果，不发起模型调用。

合成真实联调命令为 `scripts/asis-agent self-test --request-id ... --steps 1`，随后 `resume` 同一编号。它在私密 home 的 `agent-validation/` 保留固定合成来源以支持跨进程恢复；不读取 Study／Life。不要在已有未知请求上换编号自动尝试。新验证实验须有具体调整和独立记录，仍受原预算约束；初次 HTTP 429 后曾停止试验；随后增加错误分类／冷却并在新的可用窗口使用独立合成实验完成续验，没有重试两笔旧未知请求。
