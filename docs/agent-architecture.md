## 已确认的产品方向

2026-10-13，用户确认：

- 执行方式选择有限自主规划：Agent 自己拆解问题、选择工具，根据执行结果补查或调整计划；权限和资源上限由程序控制。固定领域流程可作指引，不把每项工作写死为唯一调用顺序。
- 触发方式支持用户请求与明确委托的持续工作。有限自主发起允许在预先约定的资料、主题和预算内，先检索分析、准备草稿，再提出建议；创建正式行动任务和对外写操作继续遵循既有确认规则。具体约定、发现触发、打扰频率和预算数值尚未确定。
- 系统负责工作、数据和权限，接入可替换的 Agent 执行框架；Pi 为优先验证的候选，具体组件与版本尚未选定。
- 持续工作建立独立的 Work Delegation，保有范围、进度、结果与暂停状态；每次检查或研究为关联的 Delegation Run，聊天可发起或查看委托。
- 第一版 Agent 组织采用一个总管（Supervising Agent）加三个长期专业角色（Specialist Agent）：知识研究、申请与职业、生活记录与复盘。长期角色按需执行；调度与协作协议未定。
- 各专业角色分别保有领域工作上下文，总管按当前工作获取必要结果；跨领域共享经过权限过滤。独立领域上下文不会自动将分析提升为长期个人记忆或已确认事实。
- 工具能力同时支持封装的领域工具，以及临时脚本、命令执行和浏览器操作。脚本和产物写入专用工作目录，原始资料保持只读；本项目现有环境的配置修改、依赖安装、测试后部署、服务重启和回滚已获后续持续授权，见[确认方案](private-data-authority.md)。隔离和受控来源访问的具体实现未定。
- 浏览器支持公开网页及用户明确授权的登录站点，允许读取页面和准备表单内容；提交、发送和其他远程写操作遵循既有确认规则。自动保存等有外部影响的页面行为也属于写操作。具体账户、站点、凭据和登录态接法未定。
- 专业角色间的协作请求经总管转派和汇总，总管可自动路由，不将路由操作本身变成每次询问用户的步骤。
- 每项委托可在用户设定的检查频率上下限和预算内自主调整频率，调整理由和下一次检查时间可见，用户可覆盖安排。
- 普通运行成果集中汇总；需要用户介入、即将到期或持续失败时及时通知。每项委托配置汇总频率与通知条件，继续按渠道权限过滤内容。
- 首个 Agent 版本在执行节点离线时保存进度并等待原节点恢复，恢复后继续；不自动跨节点接管执行中的运行。
- 首批外部／阅读信息源包括微信公众号、知乎、WUCAI、Folo，并新增用户指定的 `xpzouying/xiaohongshu-mcp` 小红书入口。公众号首版利用现有剪藏、收藏、分享和可用订阅；知乎选官方 CLI，关注内容覆盖待实测。具体方式与边界见 [信息来源接入讨论](information-sources.md)；尚未接入或启用订阅。
- 信息输入同时支持订阅发现和个人精选两个入口，保留各自的到达与用户选择关系；同文可出现在两个入口中，精选不自动代表用户认同或已掌握内容。
- WUCAI 首先直接适配官方只读接口，减少用户维护本地 Obsidian 的依赖；Obsidian 作为可选来源保留。读取范围和实际账号能力未配置或验证，连接器尚未实现，普通正文缓存期限已定为 30 天。
- Folo 纳入全部现有订阅并按委托主题筛选；个人精选尽量回溯全部可获取历史，订阅流主要从启用后增量获取。未进入精选的正文缓存保留 30 天；Agent 依用户认可规则自动代选部分正文进入本机精选，标注明确、保留理由和出处，允许撤销。
- 小红书同时纳入关键词搜索、分享笔记、可见收藏和首页推荐，按委托筛选；允许普通文章与非敏感批注进入 MiMo 最小上下文；Study／Life 的现有及新增日记／健康资料另获源级持续模型、本人渠道和自动记忆许可，见 [ADR 0033](adr/0033-use-standing-personal-data-and-maintenance-authorizations.md)。具体分类和账号范围未配置。
- 独立专业工作允许有限并行，所有角色的调用统一计入预算；同账号浏览器操作单独排队。并行上限、预算预留、工作依赖与排队机制尚未实现。
- 专业角色保留已确认的领域目标和约束，每项委托独立组织工作记录，执行时检索相关历史；不把领域职责绑定为一段无限追加的对话。
- 成功的临时脚本／流程可形成 Capability Proposal，包含用途、依赖、权限、验证结果与回退方式；经用户确认对应版本后注册为长期能力。注册不扩大来源或外部写权限，改变关键版本或权限后重新审阅。
- “停止这项工作”默认暂停当前持续委托及其子工作，保留成果，等待明确恢复；“只停止本轮”和“取消委托”使用明确动作区分。
- 用户移除本机精选只移除当前选择关系，不自动建立永久排除；之后 Agent 仍可按认可规则再次代选同一内容，每次代选保留新的理由和来源。实际来源删除、读取／披露权限撤销仍须执行，不能借再次代选恢复无权限内容。
- 主动长任务先返回理解、计划与状态入口，有证据后尽早给初步成果与缺口，后台继续补全；初步结果不冒充完成结果，用户可调整方向。
- 主动请求优先于普通后台工作，预留执行容量，后台可延后；即将到期的明确委托按预设规则例外处理。优先级不允许突破总预算。

对应术语 [Personal Agent](../CONTEXT.md) 已记录。上述方向面向后续 Agent 能力，不改变 PA0 的无模型边界或既有来源、云端披露、外部写操作与个人记忆授权要求。

## 已确认的运行框架边界

由本系统保有工作目标、用户行动任务、来源政策、确认范围、预算、记忆政策、设备协调与结果的权威表示；通过明确接口接入可替换的 Agent 运行框架，承担模型交互、工具调用循环及可复用的会话／恢复机制。运行框架生成下一步候选，受控工具在实际执行前落实权限，工具输出在进入模型上下文前再次落实披露政策。框架会话或恢复存储可作为运行依据，但不能未经设计就成为用户任务、确认或记忆的唯一权威。

用户选择此路线，以复用执行能力并保留系统对个人助手行为的控制；未选择以完整现成 Agent 为系统中心或自行实现全部执行循环。程序语言、具体 SDK／RPC 接法与运行存储格式仍未决定。依据：[运行框架责任边界 ADR](adr/0019-keep-assistant-authority-outside-the-agent-runtime.md)、[有限主动准备 ADR](adr/0020-allow-bounded-proactive-preparation.md)。

## 委托与角色组织

持续委托独立于聊天会话；一次委托可产生多次运行，每次运行的状态和产出归属于委托。总管和专业角色围绕这些记录协作，用户确认的行动任务仍遵循原有 Task Candidate／Confirmation 规则。持续委托的建立不等于确认它随后建议的全部行动。

用户选择知识研究、申请与职业、生活记录与复盘三个长期专业角色，由总管协调，并分别保有领域工作上下文。专业角色间的协作请求由总管转派并汇总；独立工作可有限并行，同账号浏览器操作单独排队，所有角色调用统一计入预算。具体上限和预算执行机制未定，其他模型分配也未决定。既有 PA1 单个在线本机节点执行模型分析的边界保持有效，多专业角色可与这一节点边界并存；跨节点模型综合仍未设计。

总管获取必要领域结果，跨领域共享依来源、模型提供商和输出渠道权限过滤。例如，申请分析可以接收政策允许的相关约束，不因此获得全部 journal 原文。生活角色依独立私密模型政策读取：当前 Study／Life 已获 MiMo Flash 最小分析许可，角色建立不为其他来源或模型新增披露授权。领域工作上下文用于继续既有工作，其暂定分析不会自动成为确认事实或永久个人模型。

角色持续保有已确认的领域目标和约束，工作记录按委托组织；每次执行检索相关历史以组成当前上下文。角色身份、委托身份与框架会话分别映射，不依赖某一条持续追加的聊天记录来维持全部领域工作。具体存储和检索实现未定，已确认事实、暂定分析和运行审计仍保持各自职责。依据：[委托上下文组织 ADR](adr/0029-organize-specialist-context-around-delegations.md)。

依据：[独立持续委托 ADR](adr/0021-track-continuing-delegations-outside-chat-sessions.md)、[总管与专业角色 ADR](adr/0022-organize-agents-as-a-supervisor-and-persistent-specialists.md)。

## 调度、通知与离线恢复

用户设定每项委托允许的检查频率上下限和预算，Agent 可在范围内调整频率并记录理由、展示下一次检查时间，用户可覆盖其安排。是否由具体外部事件触发、数值上限、到期与停止条件仍待配置；降低检查间隔不能扩大获准主题、资料或网络范围。

普通成果按委托约定集中汇总；需要用户介入、即将到期或持续失败时及时通知，具体阈值与渠道待配置。通知仅使用渠道获准的状态和摘要；journal 等私密内容不会因为通知紧急而进入飞书。

主动请求的长任务先回传理解、计划和状态入口；取得证据后尽早提供标明缺口的初步成果，并持续补全。主动请求优先并预留容量，普通后台委托可延后，即将到期的明确委托按配置的例外优先级处理；所有执行仍受总预算约束。

“停止这项工作”默认暂停该委托与子工作，不再自动启动下一次运行；保留当前成果，需用户明确恢复。“只停止本轮”结束当前运行但保留下次计划，“取消委托”终止该委托的后续调度且不自动恢复；取消不等同删除资料或成果。中断中的调用无法撤销既有外部效果，需保留已知／未知结果并按恢复协议处理。

执行节点离线时运行进入等待，已持久化进度保留于原节点，恢复后继续；VPS 仅记录允许的任务／节点状态。首版不把未完成运行自动迁移到另一节点，仍需设计检查点与结果未知时的恢复协议，不能把“恢复后继续”当作盲目重复外部操作。

依据：[总管路由 ADR](adr/0025-route-specialist-collaboration-through-the-supervisor.md)、[原节点恢复 ADR](adr/0026-resume-interrupted-runs-on-the-owning-node.md)。

## 通用工具与登录站点

脚本和命令只在专用工作目录写入临时文件与成果，原始来源只读。既有文件修改、软件安装和系统配置变更另设权限。领域工具与通用工具都必须通过实际执行与上下文披露检查，工作目录作为当前目录本身不构成安全隔离；具体隔离方案需后续验证。

浏览器可读取明确授权的登录站点并准备表单内容；网站、账户和允许操作逐项配置。准备内容需避开会自动保存、上传或产生其他远程变化的操作，或先取得相应写操作确认。登录凭据与会话数据保持在获准终端，接入方式未定；本轮未读取账户登录态、配置真实站点或启动浏览器自动化。

依据：[领域上下文 ADR](adr/0023-separate-specialist-contexts-and-filter-cross-domain-sharing.md)、[通用自动化边界 ADR](adr/0024-bound-general-automation-to-workspaces-and-approved-sites.md)。

## 代选与能力积累

Agent 可依用户认可的规则自动加入本机精选，保留代选标记、理由、出处与所用规则；它与用户亲自选择、作者观点和确认个人事实分别表示。移除精选不自动建立排除，未来仍可按规则重新代选，不修改原平台收藏；再次代选必须重新满足来源读取、留存与披露政策。依据：[规则代选 ADR](adr/0030-promote-reading-cache-under-approved-selection-rules.md)。

临时脚本仍按工作目录权限执行；正式注册需形成候选能力版本，列出依赖及调用关系、所需权限、合成验证结果和回退方法，由用户确认后启用。正式能力不自动获得外部写操作确认或新增读取／披露范围；能力版本及权限的关键变化需重新审阅。候选工具／技能与 Reusable Rule 分开管理。依据：[能力注册 ADR](adr/0031-review-capability-proposals-before-registration.md)。

- [coding-agent SDK](https://pi.dev/docs/latest/sdk) 可嵌入 Node.js／Bun，控制工具、模型、资源和会话；[CLI 集成](https://pi.dev/docs/latest/cli-integration) 允许通过子进程 RPC 接入其他语言。现有 Python 检索代码因此不必仅因选择 Pi 而全部重写。
- [官方权限说明](https://pi.dev/docs/latest/security) 明确 Pi 继承启动进程权限，宿主需要控制工具和隔离边界。直接启用编码 CLI 的默认工具不能替代本系统的来源与写操作政策。
- SDK 默认持久化的是对话树、分支与模型上下文；[pi-durable](https://github.com/earendil-works/pi/blob/main/packages/durable/README.md) 另提供持久任务、检查点、恢复和工具调用记录，当前标为实验性。它可以减少自建恢复基础设施，但外部副作用仍需工具自身的幂等性及本系统的确认与恢复设计。

上述事实支持优先评估复用运行框架；尚未证明 Pi 满足 MiMo 工具调用兼容性、来源披露约束、模型预算、中断恢复或跨设备任务协议。候选验收应使用合成资料，分别验证这些边界后再定框架。
