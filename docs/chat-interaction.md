# 飞书 Chat 交互（C6 首批）

2026-11-10。C6按本人要求提前推进；仍使用既有AstrBot和本人飞书私聊，没有新机器人、常驻Agent或Work派发。工程验收与手机实用验收分开。

## 怎么用

发出 `/`、`帮助`、`/帮助`、`/help` 或 `/chat`，打开会话面板。面板显示当前话题名称、就绪／处理中／待确认、待确认日历操作数量、当前会话最近一次可核对的实际模型。没有回执时显示未知，不把默认模型冒充实际作答模型。共享个人记忆仍未启用，旧会话回查参与未观测，不显示虚假的“本轮没有使用记忆”。既有批准背景仍沿用原机制，不因个人共享记忆停用而声称背景也已关闭。

卡片可新建话题、切换最近会话、归档当前会话。`/chat archived`查看归档并恢复。归档只从常用列表收起，保留原生历史；归档当前会话时先转入新话题。默认最多展示8个会话，不自动摘要、导入或改写历史。

文字备用入口：

| 命令 | 行为 |
|---|---|
| `/chat new 标题` | 新建并进入话题 |
| `/chat switch 完整标题` | 切换到唯一同名会话；有同名时用按钮 |
| `/chat archive` | 归档当前会话，保留历史 |
| `/chat archived` | 查看归档 |
| `/chat restore 完整标题` | 从归档恢复，不自动切换 |
| `/router status` | 原有路由详情 |
| `/life status` | 原有记录状态 |

按钮5分钟有效，绑定本人、来源、目标和显示时的当前会话。重复／过期／当前会话改变后不执行；生成仍在处理时不切换。执行前占位；原生修改成功但回执中断时保留未知，不自动再建或切换。C6内部操作串行；没有把原生会话API改造成跨进程事务，不承诺与其他管理入口同时竞争时具备数据库CAS语义。

只读面板、菜单和会话命令不请求模型，不成为随记、习惯或学习记录。管理菜单不发送Work任务，不触碰笔记、日历或平台内容写入确认。

## 轻量状态反馈与 Emoji

对本人普通消息／模型请求，以飞书 `Typing` reaction 表示正在处理。框架发出发送完成事件后清理本插件创建且有确切收据的状态；现有日历提案用 `OneSecond` 表示待确认，确认／取消或到期后清理；已取得的模型错误用 `CrossMark`。不以成功表情声称工具或任务已成功。

每条入站消息每阶段仅尝试创建一次，删除也先占位；无权限、失败和未知结果均不重试，不影响主回答。中断后未知创建可能残留平台表情，本批不承诺已清理所有未知远端状态。进程重启不会自动重放旧消息。取消但没有发送完成事件的原生流程，处理状态的终结仍需手机验收。

普通完整回答在展示副本上把有限已知占位符转换为Unicode Emoji；原始LLM正文、历史、用户原话不改。代码块、行内代码、引用行、含引号的行与Markdown链接保守保留。未知占位符保持原样。流式分块不做不可靠的字符替换，改由系统提示要求模型直接输出Unicode；没有把这点写成流式展示转换已完成。

reaction使用飞书类型标识，正文使用Unicode，两者不混用。类型依据见[飞书官方CLI的reaction列表](https://github.com/larksuite/cli/blob/main/skills/lark-im/references/lark-im-reactions.md)及[官方消息表情API](https://open.feishu.cn/document/server-docs/im-v1/message-reaction/create)。

## 已发布的固定菜单与按钮回调

当前AstrBot飞书适配器默认只注册普通消息事件。本插件在原生on_platform_loaded阶段、平台实例就绪后，借助同一已认证SDK Dispatcher增加两个有范围的处理器；只修改运行时映射，卸载时按对象身份撤销自己的条目，不改AstrBot安装文件、不覆盖原消息处理器。SDK接口／映射不匹配时不接管回调，普通Chat保留，卡片退为命令说明。升级前须运行实际SDK验收。

本轮已通过用户现有Chrome登录状态核对同一机器人，并在开放平台配置并发布固定菜单，飞书应用版本1.0.1显示Released／Approved。菜单为Persistent menu，不遮住输入框；新增菜单事件订阅，发布页Scope changes为None，可用范围及禁止外部群／外部私聊保持。未读取或显示App Secret，没有申请新权限。菜单传播和手机显示仍须自然使用核对。配置如下：

| 菜单文字 | 动作：推送事件 event_key |
|---|---|
| 帮助 | `asis_chat_help` |
| 会话 | `asis_chat_sessions` |
| 归档 | `asis_chat_archived` |

菜单事件application.bot.menu_v6已添加；原有card.action.trigger及其长连接配置已核对保留。菜单点击只打开面板，不直接新建／切换，重投事件不会发送第二张卡。按钮接收校验本人operator和本插件已发送的卡片ID；不接管其他卡片回调。参考[官方菜单事件](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/application-v6/bot/events/menu)。未发送前的输入框实时斜杠补全仍未接入，不以发送 `/` 后的帮助卡冒充。

## 运维和验证

`chat-ui.sqlite3`只保存私密会话归档、模型回执、按钮与投递占位、reaction收据，不保存第二份聊天历史或个人画像。它不能覆盖AstrBot原生会话，也不是共享个人记忆。回退只还原代码和配置，保留新会话、真实历史、原话与消费账目。

发布仍走`scripts/deploy-life-vps`，停服务前完成原有SDK／后台隔离／Router验收，并新增`deploy/validate-chat-ui-sdk.py`。新验收使用实际SDK和临时原生数据库：选择后下一轮取得目标会话、旧历史保留、陌生目标拒绝、回调解析、重复点击、reaction请求构造及未知不重发；网络全部由合成传输替代，没有发送飞书测试消息。

工程结果与尚缺门槛见[本批验证](validation/chat-c6-20261110.json)。手机卡片排版、真实按钮／菜单点击、reaction权限及普通聊天体验仍由本人自然使用验收。固定菜单回退需要在开放平台关闭菜单并发布对应版本；代码回退不冒称同时撤回平台菜单。
