# 飞书 `/asis` 交互卡片

本人在已绑定的 Miyuki 私聊发送 `/asis`，机器人回复原生飞书卡片。卡片可选择研究、申请职业、生活复盘或总管自动分工，选择 Study／Life／两者，填写问题；提交后在同一张卡片显示工作编号、结果和刷新／暂停／恢复／取消按钮。另有原工作编号查询和新建问题。现有文字命令继续可用。

实现依据为用户指定的[官方卡片机器人开发流程](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/quick-start/develop-a-card-interactive-bot?lang=zh-CN)、[JSON 2.0 表单容器](https://open.feishu.cn/document/feishu-cards/card-json-v2-components/containers/form-container)和[卡片回传交互](https://open.feishu.cn/document/uAjLw4CM/ukzMukzMukzM/feishu-cards/card-callback-communication)。卡片使用代码构造的 JSON 2.0，不需要创建模板或持久化 CardKit 实体。

## 传输和平台配置

复用当前 AstrBot 的 Lark socket、身份凭据与发送权限。已在用户登录的飞书开发者后台现场核对：与 VPS 配置相同的应用已经选择长连接接收回调、订阅 `card.action.trigger`，且当前配置已发布。因此未新增平台权限或修改订阅，也没有开第二条长连接争抢事件。

当前 AstrBot 4.27.3 构造的事件分发器未提供插件级卡片注册入口。插件通过官方 SDK 的 `register_p2_card_action_trigger` 创建处理器，再把该处理器安装至既有分发器的对应回调槽；保留已有非本插件回调，卸载时只恢复自身仍占用的槽。这个兼容层依赖当前 SDK 的内部映射，在 VPS 实际解释器测试；升级 AstrBot／lark_oapi 后应重新验证。

SDK 的同步回调只核对当前应用、本人、原卡片消息、范围、有效期和操作代次，保存无正文收件身份并返回 Toast／卡片。官方要求三秒内响应；转发给 Mac 的本地 socket 通信使用后台线程，模型不在回调中执行。程序随后在原卡片更新结果，沿用加密 relay、Mac 本机政策及既有投递防重。没有新增公网回调端口。

## 身份、防重与保留

卡片只能由已绑定本人在原私聊消息内操作；禁用转发，转发后的消息身份不匹配仍拒绝。每张卡片的操作有效 30 分钟，过期重新发 `/asis`。专业角色和来源选择不会创建任何根目录或模型许可。

每个卡片代次只接受一个操作，接受后递增代次；重复提交和旧恢复按钮只返回当前收件状态，不能重新启动已付费工作。已接受的操作顺序转发，后续点击状态不会丢弃先前已接受的运行。新建问题只切换卡片，不取消原工作。结果更新绑定原操作代次，旧运行结果不能覆盖较新的工作或控制状态。

VPS 的 `card_sessions`／`card_actions` 只保存本人绑定、消息／会话／工作身份、代次、指纹、时间和投递状态，不保存问题、答案、表单正文或私钥。问题和临时接收密钥只在 RAM，沿 relay 最多 15 分钟的保留约束清理；进程重启后不自动重发旧操作。新消息可用原工作编号查询或明确恢复。初始卡片发送、结果更新及原渠道发送超时均不盲目重试。

正文输出用 plain_text 分段，模型文本不能变成卡片按钮、链接或 @ 通知。飞书平台会接触本人提交的表单及获准结果；这是既有本人渠道分析范围，不把它传播到群聊或其他人。

## 验证与维护

测试覆盖表单、回调身份、转发／过期拒绝、字段及凭据过滤、重复／旧按钮、无正文持久化、服务重启未知保护、异步转发、加密结果解密及原卡片更新。SDK 测试使用实际 AstrBot／Lark 类型、分发器与请求构造器，发送 API 为合成替身；最终实际发布与平台验收见[本轮验证](validation/agent-roles-20261015.json)。

日常直接使用 `/asis`；错误或卡片过期时重新发该命令。原工作编号在 Mac 的既有 30 天／撤权政策下有效，卡片过期不等于工作取消。维护发布保留旧插件、Mac plist 和服务器代码；单节点运行见[维护说明](pa0-mac-only.md)，角色限制与质量边界见[协作说明](agent-roles.md)。
