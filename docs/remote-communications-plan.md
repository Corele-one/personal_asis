# 下一阶段：VPS 与远程渠道适配

2026-10-20 调整后，此阶段暂缓，等待本机 Pi Agent 日常使用与核心质量验收完成后，再明确恢复范围。旧 P4 编号保留；原 P2 中的远程 PWA 聊天也移至本阶段。[归档清单](archive/remote-communications-20261020.md)保存旧实现与历史依据。

## 恢复接入时的交付顺序

1. 固定本机 `conversation-session-v1` 的适配契约，定义跨设备身份、Session 归属与 request／turn 幂等映射。远程不能直接拿 Session ID 当身份凭据。
2. 建立经过认证的加密 Relay：请求、事件与回答有过期、防重、离线等待、取消和明确恢复；VPS 不持久化正文或解密密钥。
3. 在 Mac 调用 Core 前后复核来源、模型与渠道披露政策；渠道授权与本机可读分别检查，不能复用本机 HTTP 信任域直接暴露公网。
4. 先选择一个本人渠道接入，再分别适配 VPS PWA／AstrBot／飞书。适配器只做身份、协议和投递；规划、工具、预算、计费和资料权威留在本机。
5. 旧付费会话继续使用原协议；迁移若有必要，另做显式版本化方案，保留未知结果、计费及防重状态。

## 验收与运维

独立验证未绑定身份拒绝、跨 Session 越权、逐来源披露与撤权、密文过期、重复消息、断线／休眠后恢复、未知付费结果、取消与投递防重；再做实际 Mac↔VPS 往返与本人平台 UI 验收。合成测试、SDK 成功、平台回执与真人界面验收分别报告。

重启、停服、隧道配置和发布属于后续明确切片，执行前核对实际运行版本与回退材料。本轮不自动改变现有部署；历史维护持续授权不要求每次本机变更都联动部署远程服务。
