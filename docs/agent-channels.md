## 入口

PWA 的「按需 Agent」选择 Study 或 Life，输入问题，保留自动生成的工作编号。飞书仅接受原已绑定本人、既有 Lark socket 传输上的纯文本私聊：

```text
/asis agent study | 请根据材料说明证据能否支持这个结论，并列出局限
/asis agent life | 区分相关记录中的自述与暂定解释，不作诊断
/asis agent-status 工作编号
/asis pause 工作编号
/asis resume 工作编号
/asis cancel 工作编号
```

`/asis stop`／`/asis 停止` 与 `pause` 相同，默认暂停整项工作；取消不能恢复。开始时显式给一个来源 ID，Mac 再检查该来源是否已配置且获准，不因输入来源名而新增根目录或模型许可。控制／恢复不接受新问题或来源。

PWA 与飞书可以用原编号查询、暂停、取消及明确恢复同一工作。保存会话继续使用原执行协议和历史输入指纹，同时检查原会话渠道及本次目的渠道许可；输出按当前目的渠道再核验并去除绝对 URI。跨渠道不改变问题、来源或已付费步骤。

飞书先返回指令收件回执，Mac 确认后再返回执行状态或最终结果；收件不代表暂停／运行已经执行。未绑定用户、群聊、其他平台和引用消息不进入 Agent，也不回落到 AstrBot 默认模型。

## 首次检索与有界执行

生产首轮 PWA 试验中，MiMo 没有调用检索工具，程序以 `agent_answer_requires_search` 拒绝发布，已知用量 379 Token，临时管理员会话随后撤销。该请求及已付费回复保留，不通过换代次重新调用。

[MiMo 官方工具接口](https://mimo.mi.com/docs/en-US/api/chat)核查仅支持 `tool_choice=auto`；其他值可能被服务端移除，不能声称强制工具选择有效。因此本切片的新渠道工作由本机先执行一次受控 `search_notes`，再把相关最小证据交给模型，模型可决定是否补查。初始检索不是模型选择的工具调用，不伪造 assistant 工具消息；其结果作为明确标注的证据进入对话。

初始检索按相同动作事务保存，恢复时核对原文与权限后复用，不重复检索或计费。它计入原三次检索／六条证据上限，最多六轮模型、共享日 100,000／月 1,000,000 Token 预算。模型仍可拒答；流程成功不代表检索充分或结论正确。既有 CLI 默认协议及已有渠道会话保持原行为，旧付费请求的序列化与初始模式不变。

## 飞书持久性和披露

`feishu.sqlite3` 新增 `agent_routes`：仅保存指令／工作编号、绑定目标、原消息 ID、操作、指纹、时间与传输状态，不保存问题、来源正文、结果或解密密钥。路由 180 天清理；用于执行的最小防重标记继续由 Mac 保有。首次收件在发送到 relay 前落盘；传输结果未知时，重复事件只返回原收件记录，不重新执行旧暂停／恢复。

飞书临时私钥、问题和有期限的 relay 数据只在 RAM；协调服务只中转密文。完成回执在发送前再次核对 relay 密文仍有效，使用既有事务性投递身份；SDK 超时／结果未知或进程重启后不重复发送。新本人消息可查询原工作，生成一个新的状态回执；查询不会触发模型生成。插件重启可能丢失未投递结果的临时私钥，需新消息查询，不把它报告为模型结果丢失或自动重做工作。

重新绑定时丢弃旧账号 Agent 路由与 RAM 密钥，投递前仍核对当前绑定。结果包括获准的相关引用和最小摘录；飞书平台会接触回复，沿用已有本人渠道授权。第三方发送、群聊、公开传播仍不在范围内。
