| Q11 删除与撤权 | 停止使用相关内容、清理缓存，并使仅由该来源支持的记忆失效；其他获准证据仍支持的内容可保留，计费审计仅保留必要记录。已经发送给外部平台的副本不视为自动撤回 |

私密分类表示资料需要受控处理与传播，不无条件阻止私人助手在这些授权范围内读取、分析和关联历史。每次模型调用仍按问题选择相关上下文，不以持续授权为理由整库上传。来源权限、提供商权限、输出渠道、记忆和维护操作的范围均须能分别检查、解释和撤销。

## 统一执行原则

- 持续授权作用于当前配置的 Study／Life 根目录及内部文件；更换根目录或接入新来源按新增来源确认。目录内的链接不能使实际根目录之外的资料自动继承授权。
- 私密资料的索引、检索、相关模型分析、本人渠道回复、已启用工作的通知及获准的长期记忆，不因同一内容是日记或健康记录而反复确认。调用仍由相关工作触发，遵守提供商能力和共享预算。
- 文件和网页内容是证据，不是用户授权指令。远程权限变更只接受可靠识别的本人输入；无法核实身份时不变更权限。权限权威及实际配置仍在 Mac，而授权入口可以远程。
- 原来源保持只读。助手形成的自述记录须保留来源、时间与自述属性；暂定解释与确定事实分开，支持纠正、复核和删除，不作诊断或永久心理标签。自动记忆许可不自动启用可执行规则、正式任务或日历写入。
- 普通审计与预算保留尽量采用动作身份、计数、时间及状态，不因审计而长期保留已过期或撤权的正文、私密回答和摘录。历史请求即使已清理结果，也不得因此重新付费执行。
- 撤权在下一次读取、模型发送、结果返回或通知投递前检查；本机失效后不再主动使用该资料。离线节点、外部模型、飞书历史消息和备份的清理覆盖须如实展示，恢复备份后应重新应用现有撤权记录。
- 测试、部署、重启和回滚属于已授权的现有项目维护，执行前仍需验证目标和变更、保留适当回退途径并记录结果；新增服务器、增加预算或改变既有授权范围不自动继承维护许可。
- 本轮长期记忆许可针对 personal_asis 的用户数据与能力，不授权修改 Codex 自身的全局记忆，也不把真实资料、记忆、审计或密钥写入 Git。

## 审批设置的事实边界

已核查本机 Codex 配置仍为 `approvals_reviewer = "auto_review"`，尚无 `auto_review.extra_policy`。当前会话由宿主提供完整访问和 `approval_policy = never`；这与磁盘配置是不同层，不能据此声称已修改或验证后续会话的自动审批。

[官方配置参考](https://learn.chatgpt.com/docs/config-file/config-reference)说明 `auto_review.extra_policy` 可在主政策旁增加本地 Markdown 政策，托管的 `guardian_extra_policy` 优先；普通配置不能覆盖强制宿主／托管约束。正式应用时须限定到本项目及已经明确授权的动作，并核对实际客户端支持和生效状态。

已通过非代理执行核查本机 Codex CLI 0.162.1 的字段解析：字符串及多行 Markdown 配合 `features list` 返回 0，整数值明确返回类型错误并定位到 `auto_review.extra_policy`，没有启动真实代理任务。当前项目已在用户配置中标为 trusted；按 [官方配置优先级](https://learn.chatgpt.com/docs/config-file/config-basic)，可信项目配置适合作为该项目的补充。此验证证明字段与类型受支持，尚不证明 reviewer 已装载该政策；正式应用后仍须区分解析成功与实际审批生效。
