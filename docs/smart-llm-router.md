# AstrBot Smart LLM Router

本人私聊默认选择`asis_router/auto`；综合简报选择`asis_router/complex`；摘要选择`asis_router/summary`。仅复制本人会话配置，其他会话及默认物理模型保持原状。原生Agent仍管理工具与对话，Router只选择每一次生成。

模型回复按最终实际作答模型显示首行标记：🐳 DeepSeek、🍚 MiMo、💫 Gemini Flash、✨ Flash Lite、🧊 Gemma。回退后标记最终模型；简报及Dashboard纠正同样显示。标记在展示层添加，原始模型正文、工具调用、内部摘要及后续模型上下文不加标记；保存回执、提醒和本地错误提示不冒充模型回复。

## 模型与额度

|用途|优先模型|截图额度 RPM / 输入TPM / RPD|
|---|---|---|
|明确简单闲聊|Gemma 4 26B A4B / 31B|各30 / 16000 / 14400|
|日常|Gemini 3.5 / 3.1 Flash Lite|各15 / 250000 / 500|
|复杂任务|Gemini 3.8 / 3.6 Flash|各5 / 250000 / 20|
|补充|2.5 Flash Lite；2.5 Flash；3 Flash Preview|10 / 250000 / 20；其余各5 / 250000 / 20|
|付费备用|MiMo v2.6 Flash → DeepSeek v4 Flash|沿用既有账号|

3.7 Flash保留手动选择，不推测未知额度。Live、TTS、Embedding及图像生成额度不混入聊天。

日常Lite耗尽后可用补充Flash，但主要Flash各留4次给复杂任务。复杂任务依次用Flash、补充Flash、Lite、补充Lite、MiMo、DeepSeek。每次生成至多实际尝试2个免费候选，再依次尝试两个付费备用；已知不可用模型直接跳过，不排队等待额度恢复。普通生成90秒、复杂180秒总截止时间，也服从入口总超时。单个请求45秒或复杂60秒；达到超时后结果未知，停止该请求，不自动重发。

Gemma只处理封闭规则识别的简单闲聊，完整输入不超过8K，无待完成工具链／附件；不为迁就Gemma裁剪必要材料。生活记录、查询、日历与纠正用Lite或Flash，不能凭消息短就移除工具。Lite日常LOW、复杂MEDIUM；Flash为MEDIUM，Gemma不发送Gemini思考参数。

本人可在当前消息开头明确说“换DeepSeek写一版”“请用MiMo回答”“用Flash分析……”：这是本轮真实模型选择，工具循环继续沿用，下一条普通消息恢复自动。明确选择付费模型会使用既有付费账号；指定模型不可用时清楚失败，不用其他模型模仿其风格。只在引用或讨论中提及模型不触发切换。“换个聪明点的模型”、套磁信、基于全部资料综合和过去一周回顾进入复杂档，额度不足仍遵循免费降级链。

## 限流与未知结果

私密SQLite按`google-main/实际额度桶`保留最近30天元数据；不同思考档共享计数。发送前原子占用次数与估计输入，实际usage返回后校正。每分钟准入使用截图额度80%；每日用量是本地发送数，包含失败／未知发送，不等于Google官方剩余。启动首分钟保守冷却Google；其他应用的消耗只能通过上游拒绝进一步发现。

结构化QuotaFailure中的每日限制冷却至America/Los_Angeles次日零点；其他429优先遵守RetryInfo／Retry-After，无明确信息冷却60秒。503冷却60秒，连续故障最长300秒。结构化错误表明共享模型维度时合并额度桶。鉴权／配置故障隔离，来源配置改变后仅解除配置类隔离，不清零额度记录。

Google SDK与AstrBot内部重试、Key轮换、自动移除工具／系统指令及重生成均关闭。明确上游拒绝可更换当前生成；超时、断线、取消、已开始输出不重发。工具结果沿原生消息链保留，不重启Agent。空回复或无法解析的工具输出也停止，不由外层空输出重试反复请求。

## 工作上下文和隐私

原始AstrBot会话不被Router压缩覆盖。发往模型的副本目标32K，必要系统约束、当前请求及本轮工具配对完整保留；必要材料本身过大允许复杂档64K，仍超限则要求缩小范围。旧内容按需生成最多1500字目标摘要，缓存匹配历史前缀后仅处理新增尾部；超大会话首轮最多整理有界近期历史，显式说明更早未整理条数，不声称完整覆盖。摘要失败停止依赖它的生成，不静默丢弃历史继续回答。

2026-11-09修复：本人Router关闭原生摘要与轮次截断（max_context_length=-1，不指定原生摘要Provider）。三个虚拟Provider使用NATIVE_HISTORY_CAP=2147483647作为原始历史缓冲容量，使实际会话规模不触发原生token截断；它不是底层模型窗口，真实出站仍由Router限制32K/64K。不能用0关闭：AstrBot会补成128K，且启动迁移会删除fallback_max_context_tokens这个未知字段；此行为已在启动后的实际配置核验。已匹配摘要先沿用到32K预算用满，再更新旧前缀，避免每个工具步骤滚动20K边界。当前用户任务及工具调用/结果始终保留成组。摘要明确区分目标、事实、用户偏好、已完成、待处理、失败和待核对；助手说已完成不能代替工具回执。新策略首次加载只清理旧摘要缓存，不清空额度与调用记录。

旧版原生压缩已经可能改写过历史；不能据此保证历史从未被改。对已保存成历史摘要的已知错误回执，仅在工作副本中排除并标明更早原文未恢复，不覆盖原库。旧备份的恢复需单独核对，不能拿旧数据库覆盖后续聊天。

摘要缓存与诊断表分开，均仅在VPS私密目录，7天到期按需清理。缓存绑定scope和来源前缀哈希，历史修改后不能复用；本人删除、重置、新会话或撤回Life背景时保守清理缓存。凭据仍只从既有VPS私密配置解析，不进入插件配置、Git、摘要或日志。

跨会话接续使用本人限定的`conversation_memory`：`recent`返回该私聊最近20个会话索引；`search`按短关键词返回最多8段旧问答；`read`按消息索引每页6000字符读取原文；`summary`只返回7天内且前缀仍与保存原文一致的工作摘要，并标覆盖范围。每次读取都重新核对会话仍归属该私聊且未删除；不开放工具参数、任意路径或跨账号内容。没有摘要就说明未整理，不为此后台调用模型或建立全历史新索引。当前工作摘要与跨会话长期事实分开，旧助手答案不证明任务完成。

`/router status`只对绑定本人私聊开放，显示本地用量、冷却和最近模型选择。无需手工恢复每日额度，时区日界自动处理夏令时。

## 验证、部署和回退

`PYTHONPATH=src python3 -m unittest discover -s tests -p 'test_llm_router.py' -v`验证纯策略、并发预占、时间日界、摘要和失败路径；`deploy/validate-router-sdk.py`在安装的SDK中用合成模型及原生工具执行器验证两个有副作用的工具各仅执行一次，没有平台发送。

`python3 scripts/deploy-smart-router-vps`先做SDK预检并准备回退，再安装独立插件、替换两个Life原生入口、增加三个虚拟Provider并为本人复制配置。停止服务后才改会话选择，启动观察注册失败即恢复旧配置。后续`deploy-life-vps`保留已启用Router并更新其代码。

发布回退位置由部署回执给出，运行其中`rollback.sh`恢复插件、原配置与会话选择；不恢复／覆盖生活库、聊天历史或Router已消费的请求记录。私密配置备份仍含既有凭据，应作为独立敏感备份管理。

真实模型合成验收使用`deploy/router-live-check.py`，2026-11-08本任务共用持久16次上限，发送前占位，失败和未知均计入；不发送飞书、不写真实笔记或日历。API元数据可读、合成SDK通过和服务active不能替代真实模型／真人聊天验收。
